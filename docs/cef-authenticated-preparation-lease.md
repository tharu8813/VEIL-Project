# CEF authenticated preparation lease

A future CEF preparation caller can acquire a lease from the same ProtectedProfileSession that successfully authenticated and verified the registered volume. The GUID is captured only after a successful broker unlock. The lease accepts no arbitrary root or file handle: it derives the installed product profile from the production broker configuration, rejects elevated use, verifies the root on the authenticated volume, rejects redirected descendants, then acquires the existing profile.lock using FileShare.None and verifies again. Release the lease on its owning dispatcher thread before disposing the session. StillAuthorized refuses closed/released handles, wrong thread, disposed session, lock notification, and changed broker/volume status (verification failures propagate). No product startup caller, CEF process launch, broker protocol change, or native admission exists yet.

The existing WebView2 profile.lock path and behavior are unchanged. This new acquisition must replace, not duplicate, that lock in a future CEF path. The lease is a managed preparation lifetime only; it does not prove a native child identity, prevent same-user path races/hardlinks, guarantee session state during a native launch, or coordinate descendants with relock. Native bootstrap verification and child lifetime remain release blockers. Static contract regression added; Windows, BitLocker, lock contention and failure injection NOT RUN.
