# Broker authenticated-owner snapshot for future CEF startup

The new AuthenticatedOwner command returns the ordinary registered-volume status only to the same allowlisted client identity (PID, session, SID, image) which successfully unlocked the volume and whose original crash-watch process handle remains live. The current attached volume, full encryption, protection, unlock and protector state must still match. The command is serialized and read-only; it accepts no PID, path, token or secret. Ambiguous/failed unlocks never grant this ownership. Relock, detach and crash watcher retire it. Existing Status semantics and allowed client image list remain unchanged.

The desktop client exposes a read-only query for the future preparation lease, not wired into startup. This snapshot cannot be handed to a separate executable as authority; the production broker currently pins one signed client image. A separate native bootstrap admission/identity and lifetime design remains necessary. Snapshot checks do not eliminate races after the reply, filesystem TOCTOU, or prove child process ownership. Source checks and fake-backend scenarios added; actual Windows/BitLocker runtime and fake broker run NOT RUN in authoring environment. WebView2 remains the product engine.
