# CEF protected bootstrap environment plan

The future protected launcher needs a child-only environment before native initialization. `CefChildEnvironmentPlan.Build` prepares a case-insensitive, read-only copy of inherited environment data, removes inherited VEIL_CEF_* fixture/old configuration, CHROME_LOG_FILE and TEMP/TMP, and sets TEMP/TMP to the separate protected CEF scratch directory. It declares three proposed product bootstrap path variables: VEIL_CEF_PROTECTED_ROOT (root cache directory), VEIL_CEF_PROTECTED_CACHE (default cache directory), and VEIL_CEF_PROTECTED_LOG_FILE. The product bootstrap does not yet consume these variables. Unrelated variables are retained; ambiguous case-insensitive duplicates are rejected. No parent environment mutation, process start, directory creation or product registration occurs.

This is a planning contract only. A future caller must hold authenticated broker session and exclusive profile lock, complete protected directory preparation, independently validate the exact binary and environment before launch, and retain authorization until all browser/subprocesses exit. The native bootstrap must independently check session and registered volume, canonical paths and redirects before CefInitialize, set explicit CEF root/cache/log paths, and reject missing or inconsistent inputs. Environment variables are not credentials or a security boundary. No fallback to temporary or WebView2 paths. Other inherited variables, command line, OS temp behavior, crash dumps, CEF child inheritance, sandbox and outside-volume writes require separate verification.

Pure .NET regressions cover mixed-case overrides, inherited fixture removal, path mapping, parent input preservation, ambiguous unrelated names, and no directory creation. Actual Windows protected bootstrap and BitLocker runtime: NOT RUN. WebView2 remains the product engine; release gates unchanged.
