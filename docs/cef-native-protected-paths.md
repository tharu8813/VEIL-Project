# CEF native protected-path preflight

The Windows native helper verifies an explicit product root, expected volume GUID and fixed CEF root/cache/temp/log layout using read-only Win32 path/handle and volume checks. It rejects relative/aliased paths, reparse ancestors, mismatched volume identities, missing directories, log directory collisions and an existing multiply-linked log. It does not authenticate the supplied GUID or prove encryption, protector state, broker lease, or absence of all hardlinks elsewhere. Handle/path races and global writes are not solved.

The existing Win32 and WPF smoke bootstraps reject any proposed product path environment variable before CefExecuteProcess, including lookup errors, rather than using their temporary fixture profiles. They remain development-only. The standalone synthetic Windows executable tests the helper without starting a browser, using an ordinary temporary directory and its actual volume GUID. CI runs this executable after compilation; real CEF, BitLocker, authenticated broker session and protected-volume validation remain NOT RUN. A future trusted product bootstrap must independently acquire current broker evidence and invoke this helper before CefInitialize. No change to default product engine or release gates.

Integration adds explicit-length ordinal comparisons, embedded NUL rejection, and spelling validation even for an absent log. These are synthetic regression checks, not product authorization.
