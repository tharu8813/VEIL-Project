# ADR-0003 보호 프로필 볼륨의 권한 분리

- 상태 — 승인 (2026-11-23, 사용자 승인). 시작 차단 검사·브로커/가짜 백엔드·잠금 해제 클라이언트 코드는 구현했으나 실제 BitLocker 서비스 통합 미검증.
- 작성일 — 2026-11-23
- 관련 요구 — SEC-003, SEC-004, SEC-006, 게이트 A·B

## 배경과 문제

격리 VM에서 관리자가 준비한 BitLocker VHDX에 WebView2 프로필과 앱 상태를 두고 정상 잠금·사본 복원·잠금 중 시작 거부를 실측했다. 제품이 볼륨을 직접 연결하고 잠그려면 관리자 권한이 필요하다. 브라우저 전체를 관리자 권한으로 실행하면 웹 콘텐츠를 처리하는 프로세스 트리가 시스템 권한에 가까워진다. 일반 사용자 권한으로는 BitLocker 보호 상태 조회도 제한된다.

## 검토한 대안

- 브라우저 전체를 관리자 권한으로 실행 — 구현은 단순하지만 렌더러·확장·다운로드 처리의 피해 범위가 커진다. 기각.
- 사용자가 볼륨을 수동으로 관리 — 권한 문제가 없지만 자동 잠금과 시작 전 보호 상태 확인을 제품이 보장할 수 없다. 개발 검증용으로만 유지한다.
- 앱 계층 암호화(ADR-0002 코어)로 프로필 전체를 감싸기 — WebView2가 평문 파일을 직접 다루므로 현재 엔진에는 적용할 수 없다. 출시 엔진 재평가 때 다시 검토한다.
- **브라우저는 일반 사용자, 볼륨 작업만 별도 로컬 권한 구성 요소** — 권한이 필요한 동작을 고정된 소수의 명령으로 제한한다. 채택.

## 결정

### 구성

- `Veil.Desktop`은 항상 일반 사용자 권한으로 실행한다. 관리자 권한으로 실행되면 시작을 중단한다.
- 별도 Windows 서비스(가칭 `Veil.VolumeBroker`)가 볼륨 작업만 수행한다. 웹 콘텐츠, URL, 프로필 파일 내용은 다루지 않는다.
- 브로커가 허용하는 명령은 `Status`, `Attach`, `Unlock`, `Lock`, `Detach` 다섯 가지다. 임의 경로·명령·스크립트 실행 인자는 받지 않는다.

### 볼륨 식별

- 설치 시 사용자가 승인한 하나의 VHDX를 등록한다. 등록 정보는 이미지 경로, 볼륨 GUID, BitLocker 보호기 ID이며 관리자만 쓸 수 있는 위치에 저장한다.
- 명령은 등록된 볼륨 ID만 받는다. 연결 후 볼륨 GUID와 보호기 ID가 등록 정보와 다르면 즉시 분리하고 실패를 반환한다.
- 드라이브 문자는 식별에 쓰지 않는다.

### 호출자 인증

- 명명된 파이프 ACL은 등록한 사용자 SID와 SYSTEM만 허용한다. 원격 클라이언트는 거부한다.
- 연결마다 클라이언트 PID로 실행 파일 경로를 확인한다. 설치 디렉터리의 VEIL 실행 파일이고 서명이 일치해야 한다. 개발 빌드는 별도 개발 모드 설정에서만 서명 검사를 생략한다.
- 클라이언트 세션 ID가 등록 사용자의 대화형 세션과 같아야 한다.

### 잠금 해제 비밀

- 잠금 해제 암호는 브라우저 UI에서 입력받아 파이프로 한 번 전달한다. 로그, 이벤트, 진단 덤프, 디스크에 기록하지 않고 사용 직후 버퍼를 지운다.
- 오류 응답은 원인 분류만 반환하며 입력값을 포함하지 않는다. 연속 실패 시 지연을 둔다.

### 시작 차단

브라우저는 다음을 모두 확인한 뒤에만 WebView2 환경을 만든다. 하나라도 실패하면 시작을 중단하고 새 평문 프로필로 대체하지 않는다.

1. 브로커의 `Status`가 등록 볼륨, `FullyEncrypted`, `ProtectionStatus=On`, 잠금 해제됨을 보고한다.
2. 프로필 디렉터리 핸들의 최종 경로가 그 볼륨 GUID 아래에 있다.
3. 프로필 경로에 접합점이나 재분석 지점이 없다.

### 잠금과 핸들 종료

- 잠금 전에 브라우저가 WebView2 환경을 닫고 브라우저 프로세스 트리의 종료를 확인한다.
- 브로커는 강제 마운트 해제 없이 잠근다. 열린 핸들로 잠금이 실패하면 실패를 보고하고 볼륨을 연 상태로 둔다. 보안 상태 표시는 `LOCKED`로 바꾸지 않는다.
- 자동 잠금 시점은 앱 종료, Windows 세션 잠금, 절전 진입, 유휴 시간 초과다.
- 브로커는 클라이언트 프로세스 핸들을 감시한다. 클라이언트가 잠금 없이 종료되면 자식 프로세스 종료 후 같은 방식으로 잠금을 시도한다.

### 설치·제거

- 설치 프로그램이 서비스와 파이프 ACL, 볼륨 등록을 만든다. 관리자 승인은 설치·볼륨 등록·제거 때만 요청한다.
- 제거 시 볼륨을 잠그고 분리한 뒤 서비스를 삭제한다. VHDX는 사용자가 명시적으로 선택하지 않으면 삭제하지 않는다.
- 외부에서 수동 관리하는 볼륨(`--profile-parent`)은 개발 시험 경로로 남긴다. 이 경로는 보호 상태를 보장하지 않는다고 표시한다.

## 검증 증거

결정 근거는 [BitLocker VHDX 실측](../05-encrypted-profile.md#2026-11-23-bitlocker-vhdx-실측)과 [전체 데스크톱 잠금 시험](../05-encrypted-profile.md#전체-데스크톱-상태의-잠금-시험)이다. 이 ADR의 구성 요소는 아직 구현하지 않았다. 구현 후 다음을 격리 VM에서 시험한다.

- 등록되지 않은 볼륨, 다른 사용자, 서명이 다른 실행 파일, 원격 파이프 요청 거부
- 보호 해제·일부 암호화·잠긴 볼륨·재분석 지점 경로에서 시작 차단
- 열린 핸들이 있을 때 잠금 실패 보고와 상태 표시
- 브라우저 강제 종료, 세션 잠금, 절전 후 자동 잠금
- 브로커 로그·이벤트 로그·덤프에 암호가 없음
- 설치·제거 후 서비스, ACL, 볼륨 상태

### 진행 기록

- 2026-11-23 — 브라우저 쪽 시작 차단 검사 구현. 호스트에서 접합점 프로필·접합점 상위 폴더 거부와 기존 통합 시험 통과. 브로커는 아직 없으며 보호 상태 요구는 제품 실행 경로에서 켜지 않았다. [결과](../05-encrypted-profile.md#브라우저-시작-차단-검사-adr-0003-1단계)

## 결과와 잔여 위험

- 브로커는 관리자 권한으로 동작하므로 그 자체가 공격 대상이다. 명령 수를 늘리지 않고 별도 보안 검토와 퍼징을 거친다.
- 잠금 해제 중에는 같은 사용자 권한의 악성코드가 프로필을 읽을 수 있다. 이 결정은 잠긴 상태의 보호만 다룬다.
- 페이지 파일, 충돌 덤프, 볼륨 밖 TEMP 쓰기는 SEC-004에서 따로 검증한다.
- BitLocker를 쓸 수 없는 Windows 에디션(Home)은 지원 대상에서 빠진다. 대체 백엔드는 출시 엔진 재평가 때 결정한다.
- 되돌리기 — 서비스를 제거하면 개발용 수동 관리 볼륨 경로로 돌아간다. 프로필 데이터 형식은 바뀌지 않는다.

### 보호 프로필 시작 코드 진행 기록 (2026-11-23)

- `Veil.VolumeBroker`가 등록 볼륨에 대한 다섯 가지 명령과 호출자 인증, 가짜 BitLocker 백엔드를 제공하도록 코드가 추가됨. 실제 서비스 설치/실제 BitLocker 호출은 아직 시험하지 않음.
- 보호 프로필 실행 시 분리된 볼륨을 Attach하고, 보호 여부 및 잠금 상태를 확인해 비밀번호 입력 후 Unlock. 이미 해제된 볼륨은 재인증으로 인정하지 않고 시작 중단.
- 종료 시 Lock과 이번 실행에서 연결한 볼륨의 Detach를 시도하며, 실패를 별도 경고로 표시. 열린 핸들 때문에 잠금이 실패하는 상황과 클라이언트 충돌 후 잠금은 실측이 필요함.
- Windows Home용 대체 보호 백엔드, 실제 Windows Service 호스트, 세션 잠금·절전 자동 잠금은 후속 구현 대상. 출시 판정은 변경 없음.
