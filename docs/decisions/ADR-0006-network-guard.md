# ADR-0006 네트워크 보호 1단계: 표준 보호와 프록시 보호 모드

- 상태 — 채택(1단계 구현). OS 수준 강제(WFP)와 VM 누출 시험은 후속.
- 작성일 — 2026-11-23
- 관련 — [08 네트워크 보호](../08-network-guard.md), SEC-009, SEC-010, Gate D, ADR-0004·0005

## 배경

Phase 0에서 WebView2에 고정 프록시(`--proxy-server`, 폴백 없음)를 주면 프록시 장애 시 HTTP 요청이 직접 연결로 새지 않는 것을 확인했다. 앱에는 네트워크 모드가 없었다. 다운로드 금고(ADR-0005)는 VEIL이 자체 HTTP 클라이언트로 파일을 다시 받는데, 이 클라이언트는 프록시를 쓰지 않도록 고정되어 있어 보호 모드가 생기면 직접 연결로 새는 경로가 된다.

## 결정

### 모드와 저장

- 모드는 **표준 보호**(기본)와 **프록시 보호** 두 가지다. 설정은 앱 상태 파일(보호 볼륨)에 저장하고, 엔진 시작 인수에 반영되므로 **다시 시작한 뒤 적용**된다. 화면은 `선택됨`(저장, 재시작 필요) · `적용됨`(이번 실행의 엔진에 반영) · `경로 검증됨`(프록시에 실제 연결 성공) · `차단됨`(프록시 연결 실패, 직접 연결 없음)을 구분한다.
- 프록시는 `http` 또는 `socks5` 한 개, 호스트와 포트만 받는다. 사용자 이름·암호가 필요한 프록시는 이번 단계에서 지원하지 않는다(자격 증명 저장을 피함).

### 표준 보호

- **HTTPS 우선** — 사용자가 연 링크나 입력한 주소가 `http://`이고 대상이 루프백·사설·`.local`·`.test` 주소가 아니면 `https://`로 바꿔 연다. HTTPS 연결이 실패하면 경고 페이지를 보여 주고, 사용자가 명시적으로 고른 경우에만 그 호스트를 이번 실행 동안 HTTP로 연다. 하위 리소스의 혼합 콘텐츠는 엔진 기본 차단을 따른다.
- **추적 방지** — 엔진 추적 방지 수준을 Strict로 둔다. 호환성 문제는 인터넷 VM 시험에서 기록한다.
- 실제 IP 은닉을 표시하거나 약속하지 않는다.

### 프록시 보호 (실패 시 차단)

- 엔진 인수: `--proxy-server=<scheme>://<host>:<port>`, `--proxy-bypass-list=<-loopback>`(루프백도 프록시로), `--force-webrtc-ip-handling-policy=disable_non_proxied_udp`(WebRTC가 프록시를 거치지 않는 UDP를 쓰지 않음), `--disable-quic`. PAC·자동 감지·`DIRECT` 폴백은 쓰지 않는다.
- **VEIL 자체 요청**(금고 재요청)은 같은 프록시만 사용한다. 프록시 설정이 없거나 연결되지 않으면 요청하지 않는다.
- 시작할 때 프록시 주소로 TCP 연결을 시험해 `경로 검증됨` 또는 `차단됨`을 표시한다. 연결 시험은 경로 표시용이며, 차단 자체는 엔진 인수(폴백 없음)에 의존한다.

## 검증

- 로컬 자동 시험: HTTPS 우선 판정과 경고 페이지, 추적 방지 수준, 엔진 명령줄의 프록시·WebRTC·QUIC 인수, 프록시 경유 탐색과 금고 다운로드, 프록시 중단 후 탐색·금고 다운로드 모두 원 서버에 직접 요청 없음.
- **NOT RUN(통합 VM)**: 실제 DNS 질의 경로, 외부 IPv6, WebRTC 실제 ICE 후보, 절전·재개 및 네트워크 전환 중 우회, 엔진 외 프로세스(업데이트·진단)의 직접 연결.

## 결과와 열린 항목

- 프로세스 밖에서 강제하는 장치가 없으므로 엔진 버그나 엔진이 아닌 구성 요소의 직접 연결은 막지 못한다. 고강도 보호를 표시하기 전에 WFP 강제를 별도 ADR로 검토한다.
- SOCKS5에서 이름 해석이 프록시 쪽에서 일어나는지는 VM에서 DNS 추적으로 확인한다.
- Tor 모드는 이번 범위가 아니다.
