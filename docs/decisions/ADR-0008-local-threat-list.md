# ADR-0008 VEIL 위협 엔진 1.1: 서명된 로컬 위협 목록

- 상태: 채택(1.1 기반 구현). 공개 피드와 갱신 채널은 별도 결정.
- 작성일: 2026-11-24
- 관련: [ADR-0007](ADR-0007-security-manager.md), [16 보안 관리자](../16-security-architecture.md), SEC-013

## 결정 (사용자 결정 2026-11-24)

1. **실패 정책: 열고 상태 표시(fail-open)**
   - Unknown(정보 없음)과 Error(목록 손상·만료·서명 불일치·시간 초과)는 탐색과 다운로드를 막지 않는다.
   - 목록 오류는 상태 표시줄에 "위협 목록 오류"로 계속 표시하고, 보안 화면에도 사유를 보여 준다.
   - Malicious만 차단한다. SmartScreen은 이와 별개로 계속 동작한다.
2. **목록 출처: VEIL이 서명한 목록만, 피드는 아직 없음**
   - 이번 단계에서는 형식, 검증기, 엔진, 탐색·다운로드 연결, 서명 도구만 만든다.
   - Release는 앱에 내장된 공개 키(`LocalThreatList.ProductionKeys`)로 서명된 목록만 받는다. 이 키 목록은 아직 비어 있다. 그래서 출시 키를 만들 때까지 Release는 목록을 쓰지 않고, 모든 검사가 Unknown이다.
   - 시험은 Debug 전용 `VEIL_TEST_THREAT_LIST_KEY` 훅으로 임시 키를 신뢰한다. 이 훅은 Release 바이너리에 없음을 확인했다.

## 형식과 동작

- 위치: 프로필의 `security/threat-list.json`(보호 볼륨)과 `threat-list.json.sig`.
- 서명: 파일 바이트 전체에 대한 ECDSA P-256 / SHA-256 서명(DER, base64).
- 내용: `{"schema":1,"issued","expires","hosts":[...],"urls":[sha256],"files":[sha256]}`.
  - `hosts`: 나열한 도메인과 그 하위 도메인을 막는다.
  - `urls`: 프래그먼트를 뺀 주소의 SHA-256. 목록에 주소 원문을 두지 않는다.
  - `files`: 다운로드 내용의 SHA-256.
- 거부되는 목록:
  - 64 MiB 초과
  - 형식(schema) 불일치
  - 만료됐거나, 발급일이 미래(하루 넘게)인 목록
  - 서명 없음, 또는 신뢰하지 않는 서명
  - 서명 뒤 내용이 바뀐 목록
- 모든 조회는 메모리 안에서만 한다. 방문 주소나 파일 정보를 외부로 보내지 않는다. 목록에 없으면 Unknown이며, "안전함"을 뜻하지 않는다.
- **탐색**
  - 최상위 탐색과 리다이렉트를 `NavigationStarting`에서 동기적으로 검사한다. 200 ms 안에 끝나지 않는 엔진은 기다리지 않고 진행한다.
  - Malicious면 VEIL 경고 페이지를 띄운다. 계속하려면 네이티브 막대에서만 선택할 수 있다(페이지 스크립트로는 불가). 허용은 이번 실행 동안 그 호스트에만 적용된다.
  - 탭을 복원할 때는 경고 페이지 대신 원래 주소를 저장한다. 그래서 다시 열면 다시 경고한다.
- **다운로드(금고)**
  - VEIL이 다시 요청하는 모든 리다이렉트 단계의 주소를 요청 전에 검사한다.
  - 스트리밍하는 동안 SHA-256을 계산한다. 목록에 있는 파일이면 커밋 프레임 전에 중단해 발행하지 않는다. 결과는 "차단됨: VEIL 위협 목록"으로 표시한다.
- **도구:** `scripts/threat-list.mjs`(keygen·sign·url-key·file-key). 개인 키는 저장소에 두지 않는다.

## 범위 밖과 열린 항목

- 하위 프레임 탐색과 엔진이 직접 받는 리소스(스크립트·이미지)는 검사하지 않는다.
- 공개 피드 선정(라이선스·갱신 주기)과 개인정보를 지키는 갱신 채널(주소 원문 전송 금지)은 열린 항목이다.
- 출시 서명 키를 만들고 보관하는 절차(오프라인 보관, 교체)가 필요하다.
- Windows SmartScreen 정책 상태 감지는 공식 경로가 있을 때만 다룬다.
