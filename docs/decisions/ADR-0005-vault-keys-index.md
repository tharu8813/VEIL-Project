# ADR-0005 다운로드 금고의 영구 키, 암호화 목록, 복구와 내보내기

- 상태 — 채택(구현 중). 제품 모드 비밀번호 통합은 후속.
- 작성일 — 2026-11-23
- 관련 — ADR-0002(Rust age 코어), ADR-0004 1·5항, SEC-006/007/008

## 배경

Phase 4-0 프로토타입은 세션마다 새 키링을 만들어 VEIL 종료 후 금고를 열 수 없었다. 메타데이터는 메모리에만 있었고 내보내기가 없었다.

## 결정

### 키

- 키링(`vault/keyring.age`)은 기존 Rust 코어의 age scrypt 봉투다. 용도별 세 키(프로필·다운로드·백업)를 담는다.
- **복구 코드** — 금고를 만들 때 무작위 복구 코드(200비트, 5자 묶음 8개)를 생성해 같은 키를 담은 두 번째 봉투(`vault/keyring.recovery.age`)를 만든다. VEIL은 코드를 한 번만 보여 주고, 사용자가 다시 입력해야 생성을 마친다(외부 백업 확인). 애플리케이션은 코드를 디스크에 쓰지 않는다.
- **키 보관** — 비밀번호는 금고를 열 때 Rust 프로세스(`veil-vault serve`)에 전달한다. 열린 키는 그 프로세스의 메모리에 있다. C# 앱은 인증 UI와 명령 전송 중에 비밀번호를 다룬다.
- **교체** — 비밀번호 변경과 복구 코드 재발급은 같은 키를 새 봉투로 다시 감싸고 각 파일을 원자적으로 교체한다. 복구 화면을 취소하거나 두 저장 중 하나라도 실패하면 금고를 다시 잠근다. 첫 봉투가 저장된 뒤 중단되면 새 비밀번호와 이전 복구 코드가 함께 유효할 수 있다. 두 봉투를 하나의 트랜잭션으로 교체하는 작업과 내용 키 자체의 교체는 후속 단계다.
- **비밀번호 출처** — 지금은 금고가 자체 비밀번호를 묻는다. 제품 모드의 목표는 보호 프로필 비밀번호 하나로 볼륨과 금고를 함께 여는 것이다(후속). Debug 빌드 시험만 `VEIL_DEV_VAULT_PASSPHRASE`, `VEIL_DEV_VAULT_RECOVERY` 환경 변수를 쓴다. Release는 이 변수를 무시한다.

### 저장 구조

```text
vault/
  keyring.age, keyring.recovery.age   키 봉투 2개
  objects/<id>.veil                   다운로드 내용 (Download 키)
  meta/<id>.veil                      항목 메타데이터 JSON (이름, 크기, 시각, 출처 호스트)
  index/<세대>.veil                   전체 목록 JSON (캐시)
```

- 모든 파일은 Rust 코어의 인증 스트리밍 암호화이며 스테이징 후 원자적으로 발행된다.
- 목록은 가장 최근 두 세대를 보관한다. 여는 순서: 인증되는 가장 새 세대 → 유효한 목록이 없거나 객체 집합과 다르면 `meta/`에서 다시 만든다 → 메타데이터 없는 객체는 "복구된 항목"으로 표시한다.
- 시작할 때 중단된 스테이징 파일(`.veil-encrypted-*`)을 지운다.

### 내보내기

- 사용자가 고른 위치에만 평문을 만든다. 같은 폴더의 스테이징 파일에 해독하고 객체 전체가 인증된 뒤에만 이름을 바꾼다. 인증 실패 시 파일을 남기지 않는다.

## 결과와 열린 항목

- 금고를 열지 않으면 다운로드는 "금고 잠김"으로 차단한다(평문 대체 없음).
- 한 Rust 프로세스가 작업을 순서대로 처리한다. 큰 다운로드 중에는 다른 금고 작업이 기다린다.
- 후속: 제품 모드 단일 비밀번호, 내용 키 교체, 금고 백업(Backup 키), 동시 처리.
