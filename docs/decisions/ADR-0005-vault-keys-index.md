# ADR-0005 다운로드 금고의 영구 키, 암호화 목록, 복구와 내보내기

- 상태 — 채택. 제품 모드 잠금 해제 통합은 구현했으며, 실제 BitLocker 통합 시험은 남아 있다.
- 작성일 — 2026-11-23
- 관련 — ADR-0002(Rust age 코어), ADR-0004 1·5항, SEC-006/007/008

## 배경

Phase 4-0 프로토타입은 세션마다 새 키링을 만들어 VEIL 종료 후 금고를 열 수 없었다. 메타데이터는 메모리에만 있었고 내보내기가 없었다.

## 결정

### 키

- 두 age scrypt 봉투를 버전이 지정된 `vault/keyring.bundle` 파일에 저장한다. 한 봉투는 금고 암호로, 다른 봉투는 복구 코드로 열린다. 각각 용도별 세 키(프로필·다운로드·백업)를 담는다.
- **복구 코드** — 금고를 만들 때 무작위 복구 코드(200비트, 5자 묶음 8개)를 생성한다. VEIL은 코드를 한 번만 보여 주고, 사용자가 다시 입력해야 생성을 마친다(외부 백업 확인). 애플리케이션은 코드를 디스크에 쓰지 않는다.
- **키 보관** — 비밀번호는 금고를 열 때 Rust 프로세스(`veil-vault serve`)에 전달한다. 열린 키는 그 프로세스의 메모리에 있다. C# 앱은 인증 UI와 명령 전송 중에 비밀번호를 다룬다.
- **인증 정보 교체** — 복구 후 새 암호와 새 복구 코드로 감싼 두 봉투를 스테이징 파일에 저장하고 동기화한 뒤 한 번에 교체한다. 한 항목만 바꿀 때는 다른 봉투의 암호문을 그대로 보존한다. 복구 화면을 취소하거나 파일 교체에 실패하면 금고를 다시 잠근다.
- **내용 키 교체** — 현재 금고 암호를 재확인하고 새 복구 코드를 백업한 뒤 새 다운로드·백업 키를 생성한다. 객체, 메타데이터, 목록의 무결성을 검증하며 메모리를 통해 새 저장 디렉터리에 재암호화한다. 키 봉투와 데이터가 모두 준비되면 `active-generation` 파일을 한 번에 교체한다. 활성 파일 전환에 실패하면 기존 금고를 계속 사용한다. 프로필 키와 현재 암호는 유지된다.
- **기존 금고** — 분리된 `keyring.age`와 `keyring.recovery.age`는 계속 열 수 있다. 첫 인증 정보 변경에서 번들을 만들고, 발행이 끝나면 이전 파일을 정리한다. 정리가 중단되면 다음 정상 잠금 해제 때 다시 시도한다. 번들이 존재하면 인증 실패나 손상에도 이전 파일로 되돌아가지 않는다. 번들을 사용하는 금고에는 새 브리지가 필요하며, 예전에 외부로 복사된 키 봉투에는 이 교체가 적용되지 않는다.
- **비밀번호 출처** — 보호 모드에서 브로커의 잠금 해제와 경로 검증이 성공하면 같은 비밀번호로 금고를 연다. 시작 과정에서만 비밀번호를 전달하고 임시 문자·바이트 배열을 지운다. 새 금고는 첫 실행에서 복구 코드 백업 확인을 받는다. 기존 금고 또는 변경된 보호 프로필 암호를 연결하려면 기존 금고 암호나 복구 코드로 한 번 인증한다. 복구 코드로 연결하면 새 복구 코드도 발급한다.
- **취소와 개발 모드** — 보호 모드에서 금고 설정·이전을 취소하면 탐색은 계속할 수 있고 다운로드는 차단된다. 다시 시작하면 연결을 재시도할 수 있다. 금고 암호를 독립적으로 변경하는 메뉴는 개발 모드에서만 표시한다. Debug 빌드 시험만 `VEIL_DEV_VAULT_PASSPHRASE`, `VEIL_DEV_VAULT_RECOVERY` 환경 변수를 쓴다. Release는 이 변수를 무시한다.

### 저장 구조

```text
vault/
  active-generation                  내용 키 교체 후 활성 하위 디렉터리 이름
  keyring.bundle                     교체 전 키 봉투 2개. 교체 후 활성 하위 디렉터리에 위치
  objects/<id>.veil                   다운로드 내용 (Download 키)
  meta/<id>.veil                      항목 메타데이터 JSON (이름, 크기, 시각, 출처 호스트)
  index/<세대>.veil                   전체 목록 JSON (캐시)
```

- 모든 파일은 Rust 코어의 인증 스트리밍 암호화이며 스테이징 후 원자적으로 발행된다.
- 목록은 가장 최근 두 세대를 보관한다. 여는 순서: 인증되는 가장 새 세대 → 유효한 목록이 없거나 객체 집합과 다르면 `meta/`에서 다시 만든다 → 메타데이터 없는 객체는 "복구된 항목"으로 표시한다.
- 시작할 때 중단된 스테이징 파일(`.veil-encrypted-*`)을 지운다.

### 내보내기

- 사용자가 고른 위치에만 평문을 만든다. 같은 폴더의 스테이징 파일에 해독하고 객체 전체가 인증된 뒤에만 이름을 바꾼다. 기존 대상 파일은 덮어쓰지 않으며 인증 실패 시 새 파일을 남기지 않는다.

### 백업과 복원

- 금고 관리자의 **백업**은 사용자가 정한 별도 암호로 키링 봉투를 만들고, 백업 키로 객체와 항목 메타데이터를 담은 버전 지정 스트림을 인증 암호화한다. 목록 인덱스는 복원 시 메타데이터에서 다시 작성한다. 브라우저 프로필·쿠키·기록은 백업 범위에서 제외한다.
- 첫 금고 설정에서 **백업에서 복원**을 선택한다. 백업 암호로 아카이브를 열고 새 복구 코드를 확인한다. 전체 스트림과 내부 객체를 검증한 뒤 새 금고만 발행한다. 기존 금고와 백업 파일을 덮어쓰지 않는다. 보호 모드에서는 복원 후 현재 보호 프로필 암호로 연결하고, 개발 모드에서는 백업 암호가 금고의 초기 암호가 된다.
- 백업을 만들 때 손상된 객체나 메타데이터가 발견되면 발행을 중단한다. 복원 오류는 기존 금고에 영향을 주지 않는다. 디스크 부족과 실제 전원 차단 시 동작은 통합 VM 시험으로 확인한다.

## 결과와 열린 항목

- 금고를 열지 않으면 다운로드는 "금고 잠김"으로 차단한다(평문 대체 없음).
- 한 Rust 프로세스가 작업을 순서대로 처리한다. 큰 다운로드 중에는 다른 금고 작업이 기다린다.
- 내용 키 교체에는 현재 금고 크기만큼의 추가 공간이 필요하다. 전환 뒤 이전 봉투와 재암호화한 파일을 정리하며, 강제 종료나 삭제 거부 시 암호화된 파일이 남을 수 있다. 세대 디렉터리가 남아 있는 위치에는 새 금고를 만들지 않는다. 이미 외부로 복사된 백업과 키는 교체 범위에 포함되지 않는다. 전환된 금고에는 활성 저장 형식을 읽는 새 빌드가 필요하다.
- 후속: 실제 BitLocker 통합 시험과 다운로드 동시 처리.
