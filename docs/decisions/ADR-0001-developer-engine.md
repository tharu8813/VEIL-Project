# ADR-0001 개발자용 엔진으로 WebView2 선택

- 상태 — Phase 1 채택, 출시 엔진 결정 보류
- 작성일 — 2026-11-23
- 관련 요구 — FR-001/002/007/013, SR-01/03/05, SEC-001/002/003/007

## 배경

정상 로그인과 사이트 데이터의 보존을 확인하면서 프로필 암호화 및 다운로드 본문 제어 가능성을 평가해야 한다.

## 대안과 근거

WebView2와 PySide6는 같은 로컬 테스트에서 영구 쿠키와 사이트 저장소를 복원하고 GET 다운로드를 취소했다. 두 기본 프로필에서는 평문 사이트 데이터가 검출됐다. Qt C++, CEF, Chromium 포크는 API 및 유지보수 범위를 조사했다. [Phase 0 결과](../phase0-evidence.md)

## 결정

설치된 Windows WebView2 런타임과 .NET SDK로 Phase 1을 개발한다. 두 후보가 통과한 기능 범위는 같았고 WebView2는 이 환경에서 더 높은 Chromium 계열 버전과 OS의 Evergreen 런타임 배포 경로를 제공했다. 프로토타입에는 별도 테스트 데이터 폴더를 쓰고, 기본 다운로드를 취소하며, 프록시·Tor·잠금 UX는 제공 범위에서 제외한다. [WebView2 런타임 배포](https://learn.microsoft.com/microsoft-edge/webview2/concepts/distribution)

## 재평가

암호화 볼륨 방식은 엔진 호환성을 살리되 잠금 후 핸들 종료·오프라인 복사·볼륨 밖 기록을 실측해야 한다. 엔진 저장 계층 수정은 범위 제어가 가능하지만 Chromium 패치 비용이 크다. 별도 DB 암호화만으로 웹 사이트 저장소를 보호할 수 없다. 보호 저장소와 다운로드 본문 처리 경로를 입증하지 못하면 WebView2는 개발자용으로 유지하고 CEF 또는 Chromium의 저장·다운로드 계층을 다시 평가한다.
