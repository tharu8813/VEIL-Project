# ADR-0009 첫 버전 엔진 유지 및 자체 엔진 전환 경계

- 상태: 2026-11-25 개정 — Chromium 직접 포크 채택, 현재 WebView2 구현 보존, 출시 승인은 별도 보안 게이트에 의존
- 작성일: 2026-11-24
- 관련: ADR-0001, ADR-0003~0008, SEC-001~013

## 결정

기존 WebView2 어댑터는 보존하고 현재 제품 경로에서 계속 사용한다. 신규 주력 개발은 Chromium 소스 직접 포크(Chrome 브라우저 계층 + Views, Blink/V8 유지)로 전환한다. CEF나 완전 자체 렌더러를 중간 단계로 도입하지 않는다. WebView2 정식 출시를 선행 조건으로 두지 않되 ADR-0010은 기존 내부 시험에 유효하다. 신규 엔진의 활성화 및 출시를 승인하지 않는다.

## 근거와 대안

완전 자체 웹 엔진을 즉시 개발하면 웹 표준·JS·프로세스 격리·TLS·인증서·스토리지·미디어·보안 패치 등 기존 검증을 다시 수행해야 한다. 반대로 추상화 없이 WebView2 의존을 계속 추가하면 향후 전환 비용이 증가한다. 좁은 경계부터 도입하는 것이 현재 제품 검증을 유지하면서 후속 개발을 준비하는 방법이다.

Chromium 직접 포크를 선정한다. 기존 인터페이스는 현재 제품의 정책·동작 계약 파악에 활용하며, Chromium 네이티브 구조에 WPF 호스트 계약을 강제하지 않는다. 원본 소스는 외부 체크아웃, VEIL 저장소는 핀·패치·자체 모듈·테스트를 관리한다. 기존 저장 형식을 공유하지 않고 별도 마이그레이션을 검증한다. Chromium 보안 업데이트 및 위협 보호 서비스는 필수 출시 조건이다.

## 제약

- 등록된 보호 프로필·프록시·DNS·스크래치 검증을 기존 Program.CreateEngine 경로에서 유지한다.
- 네이티브 보안 이벤트와 다운로드 처리기는 최초 실제 탐색 전에 연결한다.
- 미검증 엔진 선택, 외부 어댑터 로드, 자동 엔진 전환, 평문 프로필 및 직접 연결 폴백 금지.
- 인터페이스 구현 여부, 컴파일 성공, 렌더링 성공만으로 출시 승인하지 않는다.
- 기존 보안 게이트와 실측 증거는 유지하며, 새 엔진에서는 다시 검증한다.
