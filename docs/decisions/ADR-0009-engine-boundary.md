# ADR-0009 첫 버전 엔진 유지 및 자체 엔진 전환 경계

- 상태: 개발 방향 채택, 첫 출시 승인은 보안 게이트에 의존
- 작성일: 2026-11-24
- 관련: ADR-0001, ADR-0003~0008, SEC-001~013

## 결정

첫 버전은 기존 WebView2 어댑터를 사용한다. 먼저 좁은 엔진 인터페이스를 실제 데스크톱 호출에 연결하며, 자체 엔진 구현과 활성화는 후속 버전의 별도 일감으로 분리한다. 자체 엔진이라는 표현은 현재 단계에서 독립 렌더러나 JavaScript 엔진이 구현됐음을 뜻하지 않는다.

## 근거와 대안

완전 자체 웹 엔진을 즉시 개발하면 웹 표준·JS·프로세스 격리·TLS·인증서·스토리지·미디어·보안 패치 등 기존 검증을 다시 수행해야 한다. 반대로 추상화 없이 WebView2 의존을 계속 추가하면 향후 전환 비용이 증가한다. 좁은 경계부터 도입하는 것이 현재 제품 검증을 유지하면서 후속 개발을 준비하는 방법이다.

Chromium 포크/CEF/검증된 다른 렌더러와 독립 구현은 후속 기술 검증 후보이며 아직 선정하지 않는다.

## 제약

- 등록된 보호 프로필·프록시·DNS·스크래치 검증을 기존 Program.CreateEngine 경로에서 유지한다.
- 네이티브 보안 이벤트와 다운로드 처리기는 최초 실제 탐색 전에 연결한다.
- 미검증 엔진 선택, 외부 어댑터 로드, 자동 엔진 전환, 평문 프로필 및 직접 연결 폴백 금지.
- 인터페이스 구현 여부, 컴파일 성공, 렌더링 성공만으로 출시 승인하지 않는다.
- 기존 보안 게이트와 실측 증거는 유지하며, 새 엔진에서는 다시 검증한다.
