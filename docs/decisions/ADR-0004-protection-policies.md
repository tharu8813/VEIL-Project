# ADR-0004 보호 정책: 복구 키, 점프 목록, 시스템 드라이브, 실제 사이트 시험, 다운로드 금고 범위

- 상태 — 승인 (2026-11-23, 사용자 결정). 구현과 검증은 단계별로 진행.
- 작성일 — 2026-11-23
- 관련 요구 — SEC-003/004/006/007/008, Gate A·B·C·E, ADR-0003

## 결정

1. **BitLocker 복구 키** — 보호 볼륨을 만들 때 복구 키(복구 암호 보호기)를 반드시 생성하고, 사용자가 외부에 백업했음을 확인한 뒤에만 볼륨 등록을 마친다. 복구 키를 일반 시스템 디스크에 평문으로 자동 저장하지 않는다. 키 회전(암호·복구 키 교체)과 복구 절차를 설계한다.
2. **점프 목록** — Windows 점프 목록을 통한 개인정보 노출(최근 문서, 방문 URL, 프로필 경로)을 허용하지 않는다. 차단하고 실측으로 확인한다. 현재 앱 수준 차단 시도는 실패했으므로([SEC-004 기록](../05-encrypted-profile.md#볼륨-밖-쓰기-추적-sec-004)) 다른 방법이 검증될 때까지 Gate A 미해결 항목이다.
3. **시스템 드라이브 암호화** — 현재 보호 모드는 시스템 드라이브 암호화를 필수 조건으로 한다(페이지 파일·최대 절전 파일·덤프 보호). Windows Pro 이상을 우선 지원하고, Windows Home(BitLocker 관리 기능 없음) 지원 방안은 별도로 검토한다.
4. **실제 사이트 호환성 시험** — 인터넷에 연결된 별도 격리 VM에서 진행할 수 있다. 기존 오프라인 VM(`Veil-VM-TESTER`)과 스냅샷은 보존한다. 시험 계정과 시험 데이터만 사용한다.
5. **다운로드 금고 범위** — 확장자와 무관하게 모든 파일을 대상으로 설계한다. HTTP(S) GET, 쿠키 인증 다운로드, 리다이렉트를 먼저 구현하고 POST, Blob, Data URL, Service Worker 등은 후속 단계로 확장한다. 미지원 방식은 차단하며 평문 저장으로 우회하지 않는다.

## 진행 순서

Phase 3 미반영 커밋을 PR로 반영(PR #3) → Phase 4-0(엔진 다운로드를 평문 기록 전에 가로채 Rust 코어로 전달 가능한지 검증) → 작은 파일·대용량·인증·중단·디스크 부족 시험 → 안전한 경로가 입증되면 금고 데이터 구조·UI·목록·진행률·내보내기. 기존 로그인·쿠키·기록·탭 기능은 유지하며, 보안 검증에 실패한 기능은 비보호 방식으로 대체하지 않는다.

## 결과와 열린 항목

- 1·3은 설치·브로커 등록 흐름(ADR-0003)의 변경이 필요하다. 아직 구현하지 않았다.
- 2는 차단 방법이 없으면 출시 차단 사유로 남는다.
- 4는 새 VM 준비(설치 매체, 계정)가 필요하다.
- 5는 Phase 4-0 결과에 따라 [다운로드 금고 문서](../07-download-vault.md#phase-4-0-실측-2026-11-23)에 반영한다.
