# ADR-0010: Internal Alpha 범위와 합격 기준

- 상태: 승인 (사용자 결정 2026-11-24). 이 문서는 Alpha 출시 승인 자체가 아니다. 아래 필수 항목이 모두 PASS일 때만 Alpha를 배포한다.
- 작성일: 2026-11-24
- 관련: [11 보안 게이트](../11-security-release-gates.md), [VERSIONING](../VERSIONING.md), [SECURITY_STATUS](../SECURITY_STATUS.md), ADR-0002·0003·0005·0006·0008, SEC-003~013

## 배경과 문제

첫 배포 목표는 [11 보안 게이트](../11-security-release-gates.md#릴리스-분류)의 **Internal Alpha**, 즉 "범위를 제한한 내부 시험, 미해결 위험 문서화"다. Gate A~E는 아직 모두 미통과이고, 게이트 문서에는 Alpha용 기준이 없다. 그래서 어떤 항목은 반드시 PASS해야 하고, 어떤 항목은 알려진 위험으로 문서화하고 배포할 수 있는지 정해야 한다.

## 결정

### 1. 테스터 데이터 범위

중요하지 않은 실제 계정과 일반 탐색만 허용한다.

- 허용: 일반 웹 탐색, 잃어도 되는 계정(포럼·뉴스 구독 등), 공개 파일 다운로드
- 금지: 금융·결제, 업무·회사 계정, 주 이메일과 그 이메일의 복구 경로에 쓰이는 계정, 신분증·의료·법률 같은 민감 파일, 다른 서비스와 같은 비밀번호
- 배포할 때 [알려진 위험](#알려진-위험-배포-시-테스터에게-제공) 목록과 이 데이터 범위를 함께 전달한다.

### 2. 버전

Alpha는 SemVer 사전 릴리스 **`1.0.0-alpha.N`**(N = 1, 2, …)을 쓴다. 채널은 `internal`이고 Git 태그는 `v1.0.0-alpha.N`이다. [VERSIONING](../VERSIONING.md)의 규칙을 그대로 따른다.

현재 패키지 스크립트(`Get-VeilVersion`)는 숫자 `MAJOR.MINOR.PATCH`와 Major 0만 허용한다. Alpha 전에 다음을 구현하고 시험한다.

- 사전 릴리스 식별자 `alpha`·`beta`·`rc`와 숫자 N만 허용한다. 그 밖의 문자열·빌드 메타데이터는 거부한다.
- 업데이트 순서는 허용된 SemVer 부분집합을 아래의 4자리 정수로 명시적으로 매핑해 비교한다. `alpha.1 < alpha.2 < beta.1 < rc.1 < 1.0.0`이고, 같은 버전이나 낮은 버전은 거부한다. 임의의 실행 파일 버전이나 메타데이터에서 순서를 추론하지 않는다.
- Windows 파일 버전은 별도 숫자로 매핑한다. `alpha.N → 1.0.0.N`, `beta.N → 1.0.0.(100+N)`, `rc.N → 1.0.0.(200+N)`, 안정 `1.0.0 → 1.0.0.1000`. N은 1~99로 제한한다.
- Alpha 채널에서는 사전 릴리스가 없는 안정 버전의 빌드·설치를 계속 거부한다. 안정 버전은 별도의 출시 승인 뒤에만 허용한다.
- 계약 시험(`package-maintenance-contract.test.mjs`)에 순서 비교, 잘못된 형식, 같은·낮은 버전 거부 사례를 추가한다.

### 3. 비밀번호 분실과 복구

현재 구현을 정책으로 확정한다. 각 저장소의 복구 수단은 서로 독립이다.

| 저장소 | 잠금 해제 | 분실 시 복구 | 복구 불가 시 |
|---|---|---|---|
| 보호 프로필 (BitLocker VHDX) | 프로필 암호 | 설치 때 등록·확인한 BitLocker 복구 보호기. 관리자가 오프라인으로 보관하고, 등록 후 드릴로 실제 잠금 해제를 확인한다 | 프로필 데이터 손실 |
| 다운로드 금고 | 프로필 암호에 연동(또는 금고 암호) | 설정 때 발급하는 금고 복구 코드, 암호화 백업 | 금고 파일 손실 |
| 비밀번호 관리자 | 별도 관리자 암호(12자 이상) | **없음** | 저장소를 지우고 새로 만든다 |

설정 화면과 테스터 안내에 이 표의 "분실 시 복구"와 "복구 불가 시"를 명시한다. 비밀번호 관리자는 생성할 때 "잊으면 복구할 수 없다"고 이미 안내하고 있다.

### 4. 네트워크 보호 범위

- 표준 보호: 포함한다. 실제 IP를 숨긴다고 주장하지 않는다.
- 프록시 보호: **"실험적"으로 포함**한다. 설정과 상태 표시에 "실험적 · 고강도 익명성 보호 아님"을 표시한다. OS 수준 강제(WFP), 절전 후 복귀, 외부 IPv6, 엔진 밖 프로세스는 알려진 위험으로 문서화한다.
- Tor와 익명성 모드: 포함하지 않는다.

### 알려진 위험 (배포 시 테스터에게 제공)

Alpha를 막지 않지만, 문서화해서 테스터에게 알리는 항목이다. 상세 근거는 [SECURITY_STATUS](../SECURITY_STATUS.md)에 있다.

1. 엔진이 작업 표시줄 점프 목록에 프로필 경로를 잠시 기록한다(URL·제목 없음). VEIL이 즉시 지우지만 시스템 디스크에 일시 기록이 남을 수 있다. 시스템 드라이브 BitLocker를 권장한다.
2. Windows Prefetch에 엔진이 시작할 때 연 파일 경로가 남을 수 있다(검토 중).
3. 잠금 해제 중에는 같은 사용자 권한의 악성코드, 페이지 파일, 크래시 덤프에 대한 보호가 없다.
4. 프록시 보호는 엔진 인수로만 강제한다. OS 수준 강제(WFP), 절전 후 복귀, 외부 IPv6, 엔진 밖 프로세스는 미검증이다.
5. 실제 절전·최대 절전 중 재잠금은 미검증이다(VM에서 재현할 수 없음).
6. VEIL 위협 목록은 Release용 서명 키와 피드가 없어서 검사 결과가 항상 "알 수 없음"이다. SmartScreen은 동작한다. Windows 정책으로 SmartScreen을 재정의하는 경우와 다운로드 판정은 미검증이다.
7. 자동 업데이트가 없다. 보안 패치는 관리자가 오프라인 패키지로 설치한다. 엔진(WebView2 Evergreen)은 Windows가 업데이트한다.
8. 같은 문서에서 알림을 허용한 뒤에는 사용자 동작 없는 스크립트 요청도 허용 상태를 받는다. 새 문서와 권한 철회 후에는 거부된다.
9. 렌더러 샌드박스 토큰은 직접 검증하지 않았다(엔진 기본값에 의존).
10. 설치 프로그램 GUI, 시작 메뉴 등록, 공인 코드 서명 인증서가 없다(내부 인증서 사용).
11. 비밀번호 관리자 암호를 잊으면 복구할 수 없다.

### 배포 중단 조건

다음 중 하나라도 확인되면 Alpha 배포를 즉시 중단하고 테스터에게 알린다.

- 평문 프로필 폴백, 또는 잠긴 프로필이나 금고를 키 없이 읽을 수 있음
- 보호 볼륨 밖에 사이트 데이터·쿠키·비밀번호·금고 내용이 기록됨
- 프록시 보호 모드에서 직접 연결이나 WebRTC IP 누출이 발생함
- 업데이트나 복구가 프로필·금고·등록 정보를 손상시킴

## 검증 증거

이 ADR 작성 시점의 PASS 근거는 [SECURITY_STATUS 상태 변경 기록](../SECURITY_STATUS.md#상태-변경-기록)의 2026-11-23~24 항목이다(로컬 일괄 ①, Phase 6 smoke, `async void` 점검, 오프라인 VM 일괄, Gate D 인터넷 VM).

## 결과와 잔여 위험

- 장점: 공개 Beta에 필요한 인프라(자동 업데이트 서버, WFP, 위협 목록 피드, GUI 설치 프로그램, 공인 인증서) 없이 실사용 피드백을 받을 수 있다.
- 포기한 점: 테스터가 중요한 계정을 쓸 수 없다. 프록시 보호는 익명성 보호로 홍보할 수 없다.
- 재검토 조건: 테스터 데이터 범위를 넓히려 할 때, 필수 항목을 면제하려 할 때(새 ADR 필요), 알려진 위험 1·3·4 중 하나가 실제 공격 경로로 확인될 때, Beta 준비를 시작할 때.
