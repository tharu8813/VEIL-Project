# 14. 개발 환경·의존성·보안 업데이트 운영

## 초기 환경 대상

- Windows 11 데스크톱
- Python + PySide6/Qt WebEngine: 초기 PoC 후보
- Rust: 암호화 코어 후보
- C++/MSVC/CMake: CEF/Qt C++/Chromium 검증 시 사용
- Git, 자동화 테스트, 로컬 테스트 서버

버전은 작성 시점의 '최신'이라고 고정하지 않는다. 설치 환경에서 실제 사용 가능한 버전과 공식 보안 지원 상태를 조회하고 lockfile/버전표에 고정한다.

## 프로젝트 생성

1. OS·툴체인·실행권한·Git 상태 확인.
2. PoC별 독립 디렉터리와 재현 스크립트 구성.
3. Python 가상환경/Rust toolchain 명시 및 버전 잠금.
4. CI에서 코드 포맷·정적 분석·단위/통합 테스트 수행.
5. 외부 다운로드·빌드 아티팩트의 출처와 해시/서명 검증.
6. 배포 파일은 개발자용 PoC와 보안 검증 버전을 분리.

## 프로젝트 라이선스

자체 소스는 [MPL 2.0](../LICENSE)을 적용한다. 신규 자체 파일에는 SPDX 고지를 추가하고 외부 코드의 기존 고지를 보존한다. 배포 전 소스 제공, 제3자 라이선스 및 재배포 조건은 [라이선스 안내](LICENSING.md)에 따라 확인한다.

## 공급망 보안

- 의존성 라이선스, 유지보수 상태, 보안 공지 및 업데이트 주기 조사.
- 보안 패치가 필요한 Chromium/Qt/CEF/WebView2 관련 업데이트 경로를 문서화.
- 오래된 엔진을 사용하면서 앱 자체 버전만 올려 보안 업데이트 완료로 표시하지 않는다.
- SDK/라이브러리/바이너리 공급원을 기록하고 검증된 패키지만 사용.
- 가능한 범위에서 재현 가능한 빌드 및 SBOM(소프트웨어 구성 명세) 준비.

## 의존성 업데이트 관리

[Dependabot 설정](../.github/dependabot.yml)은 NuGet(데스크톱·브로커), Cargo(보안 코어), GitHub Actions의 버전 변경을 매주 검토용 PR로 제안한다. 동시 PR 수를 제한하여 CI 부담을 줄인다. 자동 병합은 설정하지 않는다. 정확히 고정한 버전과 lockfile 변경, 보안·호환성·라이선스 영향 및 관련 CI/VM 시험 결과를 확인한 뒤 병합한다. WebView2 Runtime 자체 및 OS 업데이트는 별도로 추적한다.

Dependabot alerts 및 security updates의 활성화 여부는 저장소 Security 설정에서 별도 확인한다. 이 구성 파일만으로 해당 기능의 활성화를 보장하지 않는다. 취약점 발견 시 정기 업데이트를 기다리지 않고 [보안 정책](../SECURITY.md)에 따라 평가한다.

## 크래시·진단 및 개인정보

- 진단 로그는 기본적으로 비밀번호·키·쿠키·인증 토큰·URL/파일명을 포함하지 않도록 설계.
- 상세 진단은 사용자 명시적 동의가 필요하며 생성된 자료를 검토/정제할 수 있도록 한다.
- 크래시 덤프의 생성·위치·보관·삭제·접근 권한을 확인하고 위협 모델에 반영.
- 개발 중 보안 우회를 위한 환경변수/실행 플래그를 정식 빌드에 포함하지 않는다.

## 배포·업데이트

- 설치·제거·업데이트·버전 되돌리기 시 암호화 프로필 데이터 유지 검증.
- 암호화 데이터 포맷 변경은 마이그레이션 및 롤백 위험을 평가한다.
- 바이너리 코드 서명과 업데이트 무결성 확인 방식을 검토한다.
- 보안 취약점 접수·분류·핫픽스·릴리스 차단 프로세스를 마련한다.
