# 07. 암호화 다운로드 금고

## 제품 행동 [확정]

사용자는 일반 브라우저처럼 링크를 눌러 파일을 다운로드한다. VEIL은 파일을 보호된 금고에 저장하고 Ctrl+J에서 상태·파일명·열기·내보내기를 제공한다. 영구 파일의 평문은 **사용자가 선택한 내보내기**에서만 외부 일반 폴더에 생성한다.

## 보안 불변 조건

- 다운로드 완료 후 `%Downloads%` 같은 평문 임시 파일을 다시 암호화하는 접근은 최종 구현으로 불합격.
- 파일 내용뿐 아니라 원래 이름·원본 URL·콘텐츠 형식·시간 등 민감 메타데이터도 암호화한다.
- 암호화 실패·저장소 부족·스트림 가로채기 실패 시 보호되지 않은 디스크 경로로 자동 변경하지 않는다.
- 금고 저장 파일을 열거나 삭제할 때 파일 식별자·경로·확장자를 신뢰하지 않는다.
- 다운로드 출처와 파일의 신뢰성을 동일시하지 않는다. 악성 파일 검사·경고·샌드박스 정책을 별도로 검토한다.

## 다운로드 파이프라인 가설

```text
브라우저 다운로드 이벤트
  → 실제 응답 데이터에 접근 가능한 어댑터 [엔진별 검증 필요]
  → authenticated streaming encryption
  → 임시 암호문 객체(원자적 쓰기)
  → 무결성 확인 및 암호화 인덱스 등록
  → Ctrl+J 목록에 완료 표시
```

Qt WebEngine의 `QWebEngineDownloadRequest`는 다운로드 위치 제어 기능이 있으나 응답 데이터를 바로 암호화 스트림에 전달하는 API가 있는지 별도 검증이 필요하다. 일반 HTTP 요청만 별도 HTTP 클라이언트로 재요청하면 쿠키/서비스 워커/Blob 등과 동등한 의미가 성립하지 않을 수 있다.

WebView2에서는 실험 런타임 옵션을 켜고 일반 다운로드를 취소한 합성 GET의 본문을 메모리에서 얻었다. 시험은 작은 응답 한 건의 해시를 비교했다. 크기 한도, 인증·POST·Blob·Service Worker 응답, 원본 기록 경로는 후속 실측 대상이다. [Phase 0 결과](phase0-evidence.md)

## 테스트할 다운로드 유형

| ID | 유형 | 수용 기준 |
|---|---|---|
| D-01 | 일반 HTTP/HTTPS GET | 원본 평문 일반 디스크 기록 없이 금고 저장 |
| D-02 | 인증 쿠키 포함 | 기존 로그인 상태와 동등하게 다운로드 |
| D-03 | 리다이렉트 및 POST | 요청 방식/인증/헤더/본문 의미 보존 |
| D-04 | Blob/Data URL | 브라우저 생성 파일도 보호 또는 안전하게 차단 |
| D-05 | Service Worker | 중개된 응답을 보호하거나 명시적으로 차단 |
| D-06 | Content-Disposition | 원본 파일명·형식 안전 처리 |
| D-07 | 대용량 파일 | 메모리 전체 적재 없이 처리 |
| D-08 | 일시정지·재개 | 암호 스트림/부분 객체의 무결성 관리 |
| D-09 | 강제 종료·디스크 부족 | 부분 객체 복구/삭제 및 경고 |
| D-10 | 중복 파일명 | 내부 고유 ID, 외부 내보내기 충돌 처리 |

미지원 유형은 '지원'으로 표시하지 말고 실패를 명시한다.

## 금고 메타데이터

고유 파일 ID, 원래 파일명, MIME/확장자, 크기, 생성 시간, 출처(개인정보), 해시/무결성 태그, 다운로드 상태(대기/진행/완료/실패/손상), 암호 포맷 버전을 관리한다. 민감 필드는 암호화 인덱스에 둔다.

## 내부 열기와 내보내기

- **내부 열기:** PDF/이미지/텍스트 등 지원 범위는 후속 기술 검증과 안전한 렌더링 경계에 따라 결정. 미리보기에 사용한 원문이 영구 일반 디스크에 쓰이지 않도록 추적한다.
- **외부 열기:** 외부 앱의 일반 파일 요구와 임시 평문 생성 위험을 평가 후 구현. 안전을 검증하지 못하면 '내보내기 후 열기' UX만 제공한다.
- **내보내기:** 명시적 폴더 선택, 확장자 위장, Windows 예약 이름, `../` 경로 탐색, 파일 충돌, 중단, 복구, 무결성 오류 처리. 내보낸 평문은 금고 밖 보호 범위라는 안내를 1회 제공한다.
- **삭제:** 인덱스와 객체를 함께 정리하고 삭제의 물리적 복구 가능성(SSD/TRIM/백업)을 과장하지 않는다.

## UI 수용 기준

Ctrl+J에서 다운로드 진행률·일시정지/취소(지원 시)·열기·내보내기·삭제가 동작한다. 암호화 설정을 매번 묻지 않는다. 다운로드 불가 사유는 짧고 이해하기 쉬운 문구로 제공한다.

VEIL은 Ctrl+J에서 대기 및 전송 중인 항목별로 받은 용량과 취소 버튼을 표시한다. 전체 크기를 알면 진행 막대를 채우고, 알 수 없으면 받은 용량과 활동 표시를 보여 준다. 취소는 금고 발행이 시작되기 전까지 가능하며, 발행 단계에서는 버튼을 비활성화한다. 취소된 항목은 현재 브라우저 세션에서 상태만 표시되고 금고의 파일·암호화 목록에는 추가되지 않는다.

## Phase 4-0 실측 (2026-11-23)

범위는 [ADR-0004](decisions/ADR-0004-protection-policies.md) 5항이다. WebView2 157.0.4341.60, 개발 빌드, 호스트(일반 디스크의 합성 프로필)에서 시험했다.

### 확인한 엔진 제약

- WebView2에는 다운로드 바이트를 앱 스트림으로 넘기는 API가 없다. `DownloadStarting`이 발생할 때 엔진은 이미 응답 본문을 받기 시작했다. 작은 파일(1~4 KiB)은 본문 전체, 8 MiB는 약 1 MiB를 다운로드 임시 폴더에 기록한 뒤였다(64 MiB는 0). 이 폴더는 PR #3 이후 프로필의 `temp\downloads`(보호 볼륨)이며 취소 후 삭제되고 종료 시 비운다.
- 엔진은 받은 본문 앞부분을 **HTTP 디스크 캐시**(`Cache\Cache_Data`)에도 기록했다. 첫 시험에서 시험 페이로드가 캐시 파일에서 발견됐다. 다운로드를 취소할 때마다 디스크 캐시를 두 번(즉시, 1.5초 후) 비우도록 했고, 재시험 두 번에서 프로필의 모든 파일에 페이로드가 남지 않았다. 파일 시스템의 빈 공간에 남은 조각은 검사하지 않았다(보호 볼륨 안이다).

### 프로토타입 구조

```text
엔진 DownloadStarting → 즉시 취소, 엔진 캐시 비움
  ├ 미지원(http/https 아님, GET 아님, 금고 도구 없음) → 차단(평문 대체 없음)
  └ 지원(GET) → VEIL이 같은 URL을 다시 요청
        · 쿠키: 엔진 CookieManager에서 홉마다 조회(HttpOnly 포함), 리다이렉트는 직접 따라감(최대 10)
        · 시스템 프록시 미사용(보호 네트워크 경로는 Phase 5)
        → 64 KiB 프레임으로 veil-vault.exe 표준 입력에 전달(디스크에 평문 없음)
        → Rust 코어 age 스트리밍 암호화, 스테이징 후 원자적 발행
        → 종료 표시와 총 길이가 맞을 때만 발행, 아니면 스테이징 삭제
```

- `veil-vault.exe`(`crates/veil-security/src/bin/veil-vault.rs`): `init`/`seal`/`verify`. 단위 시험 3건 — 3 MB 정상 봉인·검증, 프레임 중간·경계에서 끊긴 스트림, 길이 불일치·잘못된 암호 모두 실패하고 **객체·스테이징 파일 없음**.
- 앱(`apps/desktop/DownloadVault.cs`): 세션마다 새 키링(메모리의 무작위 암호). **프로토타입 한계** — 앱 종료 후 객체를 열 수 없고, 메타데이터는 메모리에만 있으며, 내보내기·목록 UI는 아직 없다.

### 시험 결과 (`node tests/phase4/vault-capture.mjs`)

| 다운로드 | 결과 | 엔진이 취소 전 받은/기록한 바이트 |
|---|---|---|
| 1 KiB GET | 보관됨, 금고에서 인증 통과 | 1,024 / 1,024 |
| 8 MiB GET | 보관됨, 인증 통과 | 0 / 1,048,576 |
| 64 MiB GET | 보관됨, 인증 통과 | 0 / 0 |
| 쿠키 인증 4 KiB | 보관됨, 인증 통과 | 4,096 / 4,096 |
| 리다이렉트 후 2 KiB | 보관됨, 인증 통과 | 2,048 / 2,048 |
| 4 MiB 중 1 MiB 후 연결 끊김 | 실패, 객체 없음 | 0 / 0 |
| POST | 차단됨(미지원) | 2,048 / 2,048 |

- 종료 후 금고 폴더에는 키링과 보관된 객체 5개만 있었다. 프로필 전체 파일과 사용자 Downloads 폴더(파일 이름만 확인)에 시험 페이로드는 없었다.
- 기존 데스크톱 시험의 8가지 다운로드: GET·인증·리다이렉트·대용량은 보관됨, POST·Blob·Data URL은 차단됨, Service Worker는 실패(VEIL의 재요청은 네트워크로 가며 서비스 워커 응답을 받지 못한다). 어느 경우에도 평문 저장은 없다.

### 판단과 남은 위험

- **재요청 방식의 한계**: 같은 URL을 두 번 요청한다. 일회용 링크, 요청마다 달라지는 응답, 서버 측 다운로드 횟수 제한, 쿠키 외 인증(HTTP 인증 창, 클라이언트 인증서, 브라우저 세션 저장소 토큰)은 실패하거나 다른 결과를 받을 수 있다. 실패는 차단으로 끝나며 평문으로 우회하지 않는다. 실제 사이트에서의 성공률은 인터넷 VM 시험(ADR-0004 4항)에서 측정한다.
- **엔진 쪽 평문 조각**: 취소 전에 엔진이 받은 본문은 보호 볼륨의 임시 폴더와 캐시에 잠시 존재한다(삭제·비움 확인). 일반 시스템 디스크에는 기록되지 않는다(SEC-004 VM 추적). 금고 경로 전체의 볼륨 밖 쓰기는 VM Procmon 추적으로 다시 확인해야 한다.
- 후속 로컬 시험: 영구 키·복구·백업·내보내기와 항목별 진행률·취소 동작을 확인했다. 보호 볼륨 쓰기 추적과 디스크 부족·전원 차단 시험은 남아 있다. [보안 상태](SECURITY_STATUS.md#phase-4-영구-금고-로컬-검증-2026-11-23)

## Phase 6 다운로드 금고 UX 및 제한된 내부 미리보기 (구현·검증 보류)

- Ctrl+J의 기존 진행률·취소·결과 페이지를 유지하고 네이티브 금고 열기 버튼을 추가한다. Ctrl+Shift+J 및 설정의 기존 경로도 유지한다.
- 금고 관리 창에 파일명/출처 검색, 최신/오래된/이름/크기 정렬, 복구 항목 필터, 개별 인증 검사 및 총량 표시를 추가한다. 백업·전체 검사·암호/복구 코드/내용 키 교체는 금고 관리 메뉴로 이동한다. 작업은 창에서 직렬화하고 기존 vault gate를 사용한다.
- 내부 미리보기는 복구 항목이 아닌 256 KiB 이하 .txt에 한정한다. Rust 기존 read 명령으로 전체 인증 후 메모리에 반환하고 기록된 길이와 실제 길이를 비교한다. 엄격한 UTF-8 및 제어/방향 제어 문자 검사를 통과한 텍스트만 네이티브 TextBlock에 표시한다. HTML, PDF, 이미지, 실행 파일, 외부 앱, 임시 평문 파일은 사용하지 않는다. 파일 확장자만으로 신뢰 여부를 판단하지 않는다. 미리보기 바이트는 사용 후 지우지만 .NET 문자열·OS 메모리/덤프 삭제를 보장하지 않는다.
- 내보내기 전 금고 밖의 평문 저장을 안내하며 기존 파일 덮어쓰기를 허용하지 않는다. 예약 이름 및 잘못된 기본 파일명은 안전한 대체 이름을 사용한다. 실제 파일 발행은 기존 인증된 Rust export 경로를 사용한다.
- 항목 작업 전에 현재 금고의 ID/멤버십을 확인한다. 프로토콜 read 응답의 크기를 제한하며 잘못된 프레임은 세션을 종료한다. 삭제 및 인증 오류는 성공 또는 악성코드 판정으로 표현하지 않는다.
- **NOT RUN**: UI 및 smoke/VM 검증은 일괄 검증 단계에서 수행한다. 실제 데이터로 사용하기 전 보안 출시 게이트를 통과해야 한다.

### 일괄 검증 추가 항목

- [ ] Ctrl+J 진행률/취소/금고 열기, 검색·정렬·복구 필터·선택 유지·다중 창 및 작업 중 중복 실행
- [ ] 합성 TXT/UTF-8 BOM/빈 파일/경계 크기/이진 및 잘못된 UTF-8/제어 문자/암호문 손상/복구 항목
- [ ] 미리보기에서 네트워크·임시 평문·외부 프로그램 실행 없음, 보호 볼륨 밖 쓰기 추적, 잠금 중 창/프로세스 종료
- [ ] 개별/전체 인증, 기존 파일 충돌 및 취소, 예약 이름, 삭제·인덱스 오류, 백업·키 변경 회귀

### 금고 관리 메뉴 회귀 자동화 (2026-11-25)

기존 `vault-backup` smoke의 폐기용 복원 금고에서 실제 네이티브 메뉴 이벤트와 복구 코드 마법사 버튼을 조작하는 Debug 전용 시험을 추가했다. 백업 선택·마법사 취소, 백업 충돌, 내용 키 교체 확인·복구 코드·현재 암호 취소, 잘못된 암호, 정상 교체 후 메타데이터·이전 백업·새 복구 코드·기존 파일 인증을 확인한다. 실제 Windows 실행은 NOT RUN. 메뉴 팝업 표시·물리 입력·보호 볼륨 및 전원 차단은 별도 검증 대상이며 C2 상태는 변경하지 않는다.


### 저장 실패 및 복구 통합 검사 (2026-11-25)

- Rust 봉인 응답의 고정 오류 종류 `StorageFull`만 저장 공간 부족으로 분류한다. 원문 오류/경로는 표시하지 않고, 발행 단계에서는 목록 확인 필요를 함께 표시한다. 자동 재시도 또는 평문 폴백은 없다.
- `vault-publication`: 새 합성 금고의 메타데이터/인덱스 디렉터리를 각각 임시로 막아 실제 파일시스템 쓰기 오류를 발생시키는 Debug 시험이다. 앱 캡처 경로의 실패 표시, 원본 암호문과 이전 인덱스 보존, 잠금 후 목록 재구성, 메타데이터 없는 객체의 복구 표시와 인증 길이, 이후 새 요청, 중복·스테이징·평문 잔존을 검사한다. 완성된 암호문은 ADR-0005에 따라 복구 대상으로 유지하며 성공으로 보고하지 않는다.
- `tests/phase3/phase34-vm.mjs`의 기본 보호 볼륨 시험 목록에 추가했다. **NOT RUN**: 실제 Windows/BitLocker 실행. 이 시험은 실제 ENOSPC, 전원 차단 또는 WebView2 DownloadStarting부터의 통합 시험이 아니다. 기존 `vault-disk-full` Rust 경계 시험 외에 실제 C# HTTP/파이프 경로의 공간 부족 및 발행 시점 ENOSPC는 별도로 검증해야 한다. C2는 미통과.


### 실제 공간 부족 데스크톱 브리지 시험 (2026-11-25)

- `vault-bridge-disk-full`: 기존 Rust 코어 단독 시험과 동일한 오프라인 VM preflight를 재사용한다. 별도 소형 BitLocker 시험 볼륨의 GUID, 정규 경로 및 용량을 검증하며 기본 보호 볼륨에는 브라우저·시험 증거만 둔다.
- 기본 파일을 저장한 후 별도 시험 볼륨의 가용 공간을 약 2 MiB로 제한한다. 8 MiB 합성 GET을 C# HTTP/파이프/Rust 봉인 경로로 요청하여 실제 `StorageFull` 응답, 기존 객체·메타데이터·인덱스 해시 보존, 실패 객체 및 스테이징 미발행, 기존 파일 인증을 검사한다. 공간을 확보한 뒤 금고를 다시 열어 명시적 새 요청과 중복 없는 저장을 확인한다.
- VM 일괄 시험에 등록했다. **NOT RUN**: Windows/BitLocker VM 실행. WebView2 DownloadStarting 이벤트부터의 실제 공간 부족, 메타데이터/인덱스 발행 순간의 실제 ENOSPC 및 전원 차단 시험은 별개로 남는다. C2는 계속 NOT RUN.

### 실제 메타데이터·인덱스 발행 공간 부족 시험 (2026-11-25)

- `vault-publication-full-meta`, `vault-publication-full-index`: 기존 C# 브리지 러너에 두 개의 별도 모드를 추가했다. 본문 인증·발행이 끝난 뒤 Debug 전용 인스턴스 콜백이 메타데이터 또는 인덱스 쓰기 직전에 기다린다. 외부 러너는 동일한 오프라인 VM preflight를 재확인하고 별도 2 GiB 이하 폐기용 BitLocker VHDX에서 실제 할당 공간을 소진한다. 제품의 Rust 쓰기 오류를 모의하지 않는다. 작은 쓰기가 성공하거나 다른 오류가 발생하면 시험 실패다.
- 고정 `StorageFull` 오류, 발행 불확실 시 잠금, 기존 암호문·이전 인덱스 보존, 완성된 암호문만 보존, 실패 스테이징 미발행을 확인한다. 공간 확보 후 메타데이터 없는 객체는 복구 항목으로, 메타데이터가 있는 객체는 원래 이름으로 표시되어야 하며 각각 인증과 명시적 새 요청·중복 방지를 검사한다.
- VM 일괄 계획의 별도 두 항목이며 작은 볼륨이 없으면 NOT RUN이다. Debug 배리어는 Release에 없다. 실제 Windows/BitLocker 시험은 **NOT RUN**; 일반 다운로드 UI 이벤트 및 전원 차단·키 교체 중단의 증거는 별개다. C2는 계속 NOT RUN.

### 내용 키 교체 프로세스 중단 회귀 (2026-11-25)

Rust 단위 시험 전용 실행 파일에서 새 암호화 세대 준비 후 활성 세대 마커 교체 직전, 그리고 마커 교체 후 이전 세대 삭제 직전에 각각 자식 프로세스를 강제 종료한다. 재시작 시 활성 세대 선택, 기존/신규 복구 코드의 올바른 수락·거부, 현재 암호, 본문·메타데이터·인덱스 인증, 이전 암호문 보존과 세션 잠금 해제를 확인한다. 이전 암호화 세대가 남는 것은 의도적으로 보존하며 삭제 완료 또는 과거 복구 코드의 모든 사본 무효화를 주장하지 않는다. 중단 지점은 `cfg(test)`로 제품 Debug/Release 바이너리에 포함하지 않는다. 실제 VM 전원 차단과 저장장치 내구성은 **NOT RUN**, C2는 변경하지 않는다.


### 내용 키 교체 전원 차단 준비 (C2)

프로필/다운로드 스트리밍 시험과 별도로 폐기용 오프라인 VirtualBox VM의 보호 볼륨에서 실행한다. 호스트의 동일 커밋에서 다음 명령으로 Rust 라이브러리 단위 시험 실행 파일을 만든다.

```powershell
cargo test --locked --manifest-path crates/veil-security/Cargo.toml --lib --no-run
```

출력된 라이브러리 시험 실행 파일(veil_security-해시.exe)을 시험 번들과 함께 읽기 전용 매체로 게스트에 전달한다. 제품 실행 파일이나 일반 Debug 바이너리는 사용할 수 없다. 예시는 등록된 ProfileParent가 V:\lab인 경우이다. 현재 부팅의 관리자 preflight와 일반 사용자 게스트 셸이 필요하다.

```powershell
node tests/phase4/rotation-power-loss.mjs --arm --isolated-vm --phase before-marker --preflight C:\lab\preflight-before.json --evidence V:\lab\power-loss-rotation-before --test-exe C:\lab\veil_security-test.exe
```

ARMED 이후 45초 이내에 운영자가 지정된 폐기용 VM의 전원 차단을 수행한다. 정상 종료/시간 초과는 disarmed 증거로 남고 재사용하지 않는다. 재부팅하고 같은 VHDX를 다시 연결 및 잠금 해제한 후 새로운 preflight를 생성한다.

```powershell
node tests/phase4/rotation-power-loss.mjs --check --isolated-vm --confirm-power-cut --phase before-marker --preflight C:\lab\preflight-after.json --evidence V:\lab\power-loss-rotation-before --test-exe C:\lab\veil_security-test.exe
```

두 번째 시험은 새로운 증거 폴더 power-loss-rotation-after와 --phase after-marker로 양쪽 명령을 실행한다. 두 시험 모두 VM UUID, 다른 부팅, 동일 보호 볼륨/경로/실행 파일 해시, 정확한 중단 시점, 기존 객체/메타데이터/인덱스 암호문 해시를 연결한다. 재부팅 후 활성 세대 선택, 올바른 복구 코드와 현재 암호, 인증된 내용, 이전 암호문 보존을 검사한다. 이전 세대 잔존은 삭제 완료로 간주하지 않는다. 실제 호스트 전원 차단 기록은 운영자가 별도로 보존한다. **NOT RUN**: 실제 Windows VM 실행, 제품 Release 통합, 물리 저장장치 내구성. C2 미통과 유지.

### 인증된 인덱스 및 메타데이터의 구조 검증 (2026-11-25)

인증 복호화가 성공해도 인덱스가 null이거나 잘못된 항목, 중복 ID(대소문자 변형 포함), 유효하지 않은 GUID, 빈 이름, 음수 크기를 포함하면 해당 세대를 사용하지 않는다. 이전 정상 인덱스 후보를 검사하고 기존 객체 집합과 맞지 않거나 정상 후보가 없으면 기존 재구성 경로를 사용한다. 개별 메타데이터 역시 구조 및 객체 ID가 맞아야 채택하며 그렇지 않으면 원본 객체를 삭제하지 않고 복구 항목으로 남긴다. 복호화한 JSON 바이트는 파싱 후 지운다(.NET 문자열과 OS 메모리 삭제 보장은 아님). Debug smoke의 합성 구조 검사 및 CI 정적 계약 시험 추가. 실제 Windows 금고 복구·전원 차단 및 파일 객체 전체 인증은 별도 시험이며 NOT RUN, C2 유지.

### 대기 중 다운로드의 금고 세션 변경 차단 (2026-11-25)

GET 및 개발용 인라인 다운로드는 요청 시점의 키 보유 프로세스에 연결한다. 슬롯 대기 후, HTTP 요청 전(위협 확인·쿠키 조회 후 포함), 응답 수신 후 및 봉인 게이트 획득 후 동일 프로세스의 잠금 해제 상태를 다시 확인한다. 잠금/재개방 이후 이전 요청은 자동 재시도 없이 실패한다. 이미 발행된 객체는 변경하지 않는다. Debug 전용 HTTP 응답 경계에서 금고를 잠갔다 열고 기존 요청이 발행되지 않는지 확인하는 회귀 시나리오와 CI 정적 계약 검사를 추가했다. 실제 Windows smoke는 NOT RUN. 진행 중 프레임 전송과 강제 종료의 전체 경쟁 조건은 별도 검토 대상이며 C2 상태는 유지한다.

### 프레임 전송 중 금고 잠금 및 프로세스 종료 (2026-11-25)

잠금 시 바이너리 프레임에 텍스트 quit 명령을 삽입하지 않는다. 접근을 즉시 차단하고 키 보유 프로세스를 종료한 뒤 제한 시간 내 종료를 확인한다. 종료를 확인하지 못하면 프로세스 참조를 보존하며 새 금고 개방도 기존 프로세스 종료 확인 전에는 진행하지 않는다. 프레임 경계 및 메타데이터·인덱스 발행 경계에서 세션을 재검증하며 이미 닫힌 세션에 abort 프레임을 보내지 않는다. 강제 종료로 남은 암호문 스테이징은 기존 재개방 정리 경로를 사용한다. 이미 완성된 암호문은 임의로 삭제하지 않는다. Debug 프레임 경계 잠금/재개방 시험 및 CI 정적 계약을 추가했다. 실제 Windows 실행, 종료 실패 및 전원 차단 내구성 검증은 NOT RUN; C2 상태 유지. 잠금 시 기존 유휴 프로세스도 종료 방식으로 통일하였다.

### 제한된 금고 명령 및 복호화 응답 시간 제한 (2026-11-25)

일반 명령의 전송·flush·응답에 120초, 제한된 복호화 본문의 수신에 30초를 적용한다. 시간 초과 및 일반 명령 통신 실패 시 기존 세션을 종료하고 명시적 재개방을 요구하며 읽기 실패 버퍼는 지운다. 전체 객체 검증·내보내기·백업·복원·내용 키 교체는 작업량에 따라 시간이 달라지므로 이번 강제 시간 제한의 대상에서 제외했다. 특히 외부 내보내기 프로세스 중단 후 평문 스테이징 위험은 별도 검토 대상이다. Debug 시험에서 실제 헬퍼 응답 수신을 인위적으로 지연시키고 시간 초과 후 재개방과 기존 객체 인증을 검사한다. 이는 실제 OS 파이프 정지 재현은 아니다. 실제 Windows smoke 및 보호 볼륨 시험 NOT RUN; 시간 제한 값은 실측 전 잠정값이며 C2 유지.
