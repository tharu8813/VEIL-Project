# 02. 보안 위협 모델

## 목적과 보안 경계

VEIL이 보호하려는 대상과, 브라우저 혼자 완전히 막을 수 없는 공격을 명확히 구분한다. 보안 주장은 공격자의 권한과 브라우저의 잠금 상태를 지정해야 한다.

### 자산

- 마스터 비밀번호와 파생/보관된 암호화 키
- 쿠키·인증 토큰·사이트 로컬 저장소·방문/검색 기록
- 암호화된 다운로드 원본 및 파일명·URL·시간 메타데이터
- 북마크·비밀번호·세션 복원 데이터·사용자 설정
- 네트워크 경로 설정·프록시 인증 정보·잠금 상태
- 브라우저 및 업데이트 바이너리의 무결성

### 신뢰 경계

1. 렌더러 프로세스의 웹 콘텐츠 ↔ 브라우저 상위 프로세스
2. 브라우저/서비스 ↔ 암호화 저장소
3. 잠금 해제된 키 메모리 ↔ 운영체제·타 프로세스
4. 브라우저 ↔ OS 네트워크 스택·프록시·원격 사이트
5. 업데이트 공급망 ↔ 사용자 설치 환경

## 공격자별 목표

| 시나리오 | 위협 | 보호 목표 | 제약/잔여 위험 |
|---|---|---|---|
| T-01 잠긴 상태에서 저장소 복사 | 디스크 이미지·파일 복사 | 키 없이 쿠키/기록/문서 내용을 복원 불가 | 파일 크기·존재·수정 시각 등 메타데이터 일부 노출 가능 |
| T-02 다른 Windows 일반 사용자 | 계정 간 접근 | ACL/키 보호로 임의 열람 억제 | 관리자 권한으로 상승 시 경계 약화 |
| T-03 사용자 계정의 악성코드 | 실행 중 파일·메모리 접근 | 노출 면적 최소화 | 잠금 해제 상태에서 완전 차단 불가 |
| T-04 관리자·커널 공격자 | 프로세스/메모리/디스크 감시 | 정직한 한계 고지 및 표면 축소 | 강한 보안 보장 불가 |
| T-05 악성 웹페이지 | XSS, 웹 엔진 취약점, 권한 남용 | 최신 엔진, 렌더러 격리, 권한 최소화 | 제로데이 취약점 가능 |
| T-06 네트워크 관찰자 | DNS, IP, 트래픽 패턴 관찰 | 선택 모드 범위 내 정보 노출 축소 | 외부 서버 기록·타이밍 완전 은닉 불가 |
| T-07 무결성 공격 | 금고 일부 변경·복구 조작 | 인증 암호화/검증/복구 실패 처리 | 과거 유효 상태 재생(replay) 가능성 별도 대응 필요 |
| T-08 악성·손상된 업데이트 | 공급망 변조 | 서명 검증, 안전한 업데이트 | 공급자 신뢰와 취약한 의존성 위험 지속 |

## 암호화의 범위와 한계

- **저장 중 암호화(at rest)**는 잠긴 저장소 복사 공격을 주로 방어한다.
- **사용 중(in use)** 페이지 렌더링·쿠키 조회·파일 미리보기에는 평문이 메모리에 존재할 수 있다.
- 암호화 가상 볼륨이 열려 있으면 동일 권한의 프로세스가 볼륨에 접근할 수 있는지 검증해야 한다.
- 운영체제 페이지 파일, 최대 절전, 크래시 덤프, Windows 저널, 백업, 안티바이러스 검사 자료 등은 보장 범위와 통제 가능성을 각각 분류한다.
- 파일명이 무작위라도 파일의 존재와 용량, 접근 패턴까지 완전히 숨긴다고 주장하지 않는다.
- 브라우저는 ISP·VPN 제공자·사이트 서버의 로그를 삭제할 수 없다.

## 필수 보안 요구사항

- SR-01: 민감한 영구 데이터는 잠긴 상태에서 키 없이 복호화할 수 없어야 한다.
- SR-02: 인증 암호화를 사용하고 잘못된 키/변조 데이터에 대해 실패해야 한다.
- SR-03: 보호 저장소 실패 시 평문 프로필 또는 평문 다운로드로 자동 폴백하지 않는다.
- SR-04: 잠금은 UI 오버레이만으로 구현하지 않는다. 백그라운드 프로세스·핸들·키 수명을 포함한다.
- SR-05: 브라우저 샌드박스를 테스트 편의상 끄지 않는다.
- SR-06: 보호 네트워크 모드에서 프록시 장애 시 직접 연결로 전환하지 않는다.
- SR-07: 외부 내보내기로 보호 범위를 벗어나는 사실을 사용자에게 알린다.
- SR-08: 보안 미검증 기능을 '안전함', '익명' 등으로 표기하지 않는다.

## 검증 방법

로컬 실험 전용 OS 계정/VM, 테스트 사이트, 테스트 전용 비밀 문자열과 파일을 이용한다. Procmon/ETW 또는 동등한 도구로 파일 및 네트워크 경로를 추적하고, 디스크 스냅샷·재실행·강제 종료 시나리오를 관찰한다. `grep`으로 원문이 안 나온다는 결과만으로 저장 경로 안전성을 확정하지 않는다.

새 위협이 발견되면 `SECURITY_STATUS.md`에 등록하고 `11-security-release-gates.md`의 차단 항목에 반영한다.

## Phase 0 관찰 사항

두 엔진의 기본 프로필에서 합성 사이트 데이터가 평문으로 검출됐다. 개발자용 WPF의 북마크·방문 기록·탭 정보도 테스트 프로필의 평문 JSON에 저장된다. T-01 보호를 입증하려면 엔진의 파일과 앱 상태를 모두 보호하고, 프로필 바깥의 임시 파일·로그·시스템 기록도 조사해야 한다. WebView2와 Qt 데이터 경로 및 다운로드 취소의 계측 범위는 [Phase 0 결과](phase0-evidence.md)에 기록했다.
