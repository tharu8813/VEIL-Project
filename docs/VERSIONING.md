# VEIL 버전 관리 정책

## 기본 규칙

VEIL 제품은 [Semantic Versioning 2.0.0](https://semver.org/) 형식인 `MAJOR.MINOR.PATCH`를 사용한다. 이는 향후 운영 규칙이며 기존 빌드 번호, Rust 크레이트 버전, 개발 단계(Phase), 보안 엔진 버전을 소급 변경하지 않는다.

| 구분 | 의미 | 예시 |
| --- | --- | --- |
| MAJOR | 호환성을 깨는 제품 계약·저장 형식 등 주요 변경 | 1.0.0 → 2.0.0 |
| MINOR | 호환성을 유지하는 사용자 기능 추가 | 1.0.0 → 1.1.0 |
| PATCH | 호환되는 버그·보안 수정 | 1.0.0 → 1.0.1 |

보안 수정이 호환성을 깨면 그 영향에 맞는 버전을 올리고 마이그레이션·복구 절차를 안내한다. 지원되는 파일 형식·설정·프로필 및 사용자 기능 계약을 버전 판단 기준으로 삼는다.

## 출시 단계

- 개발 중인 빌드는 커밋 SHA로 식별한다. 개발자용 0.x 버전을 사용할 수 있으나 공개 버전으로 표시하지 않는다.
- 첫 안정 버전 목표는 `1.0.0`이다. 검증 전에는 정식 버전이 아니다.
- 내부 시험 또는 검증된 사전 릴리즈에 `1.0.0-alpha.1`, `1.0.0-beta.1`, `1.0.0-rc.1` 등의 접미사를 사용한다. 공개 베타는 해당 범위의 보안 게이트 충족 이후에만 허용한다.
- Git 태그는 `v1.0.0` 또는 `v1.0.0-beta.1`처럼 제품 버전에 `v` 접두사를 붙인다. 공개한 태그와 배포 파일은 덮어쓰거나 재사용하지 않는다.

## Windows 및 내부 구성 요소

제품 표시 버전은 SemVer 문자열을 유지한다. Windows 파일/제품 버전이 숫자 4개를 요구하는 경우 설치·업데이트 비교 규칙을 확정한 뒤 별도 숫자 매핑(예: 안정 버전 `1.2.3.0`)을 적용한다. 사전 릴리즈의 숫자 순서와 안정 버전 업그레이드 가능성을 반드시 검증한다.

Rust 크레이트, 보안 엔진, 프로필/금고 데이터 형식의 버전은 제품 버전과 별개로 관리할 수 있다. 변경 시 호환성, 마이그레이션 및 롤백 정책을 기록한다. 실제 버전 자동 동기화는 설치·업데이트 시스템 구현 시 별도 작업으로 진행한다.

## 릴리즈 절차

1. [CHANGELOG](../CHANGELOG.md)의 Unreleased 항목과 기준 커밋을 검토한다.
2. [보안 릴리즈 게이트](11-security-release-gates.md) 및 [라이선스 준수 절차](LICENSING.md)를 검증한다.
3. 버전·설치/업데이트 메타데이터·변경 기록을 일치시키고 필요한 빌드, 서명, 복구, 업데이트 시험을 완료한다.
4. 유지관리자 승인 후 해당 커밋에 태그를 만들고 동일 소스에 대응하는 배포물을 발행한다.
5. 릴리즈 기록에는 버전, 날짜, 지원 환경, 검증 범위, 알려진 제한 및 소스 취득 방법을 포함한다.

현재는 공개 배포 전이다. 이 문서 추가만으로 버전 변경, 태그 생성, 릴리즈 발행을 수행하지 않는다.
