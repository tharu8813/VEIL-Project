# 06. 암호화·키 관리·잠금·복구

## 암호화 원칙

- 검증된 암호화 라이브러리만 사용한다. 직접 알고리즘·암호 포맷을 발명하지 않는다.
- 암호화뿐 아니라 **무결성/인증**, 키 분리, 랜덤 nonce, 손상 감지를 필수로 다룬다.
- 알고리즘 후보: Argon2id(비밀번호 기반 KDF), XChaCha20-Poly1305(AEAD), libsodium secretstream(스트리밍 파일), SQLCipher(별도 SQLite 저장 시 후보).
- 보안 코어는 Rust 후보지만, 암호 라이브러리와 바인딩 안전성에 따라 확정한다.
- 실제 KDF 파라미터와 파일 헤더 포맷은 성능/버전/라이브러리 검증 후 ADR로 확정한다.

## 키 계층 (권장 개념)

```text
[마스터 비밀번호] --Argon2id--> [암호화된 마스터 키 래핑용 키]
                                      |
                               [데이터 마스터 키]
                              /        |         \
                     프로필용 키   파일 금고용 키   메타데이터/백업용 키
```

그림은 논리 개념으로, 실제 파생 방법은 충돌 없는 도메인 분리·KDF·키 래핑 규격을 확정해 구현한다.

## 요구사항

- 비밀번호는 저장하지 않는다. 검증에 필요한 제한된 자료와 salt·KDF 파라미터만 유지한다.
- 파생 키/데이터 키를 소스, 진단 로그, 예외 메시지, UI 상태, 환경 변수에 평문으로 넣지 않는다.
- 키 로테이션과 데이터 포맷 버전 관리, 실패 시 복구/원자적 교체를 설계한다.
- 암호문을 조작하거나 잘못된 키로 읽으면 반드시 인증 실패로 처리한다.
- 파일과 블록의 순서 변경·일부 삭제·이전 버전 복원(replay) 공격 가능성을 모델링한다.
- 대용량 파일은 메모리 전체 적재 없이 스트리밍으로 처리한다.

## 잠금 UX와 내부 동작

- 첫 설치 시 마스터 비밀번호를 설정한다.
- 다음 실행부터는 잠금 해제가 필요하다. Windows Hello는 **선택적** 빠른 인증 수단으로 검토한다.
- 잠금 시 UI만 가리는 것으로 끝내지 말고 네트워크/웹 스크립트, 파일 핸들, 암호화 키의 수명 등을 통제한다.
- 잠금 해제된 상태에서 OS의 다른 관리자·악성코드가 메모리를 볼 가능성을 보안 문서에 명시한다.
- 비밀번호·키 분실 시 무조건 복구 가능하다고 안내하지 않는다.

## 백업과 복구

- 사용자 명시적 암호화 백업 내보내기, 복구 키 제공 여부, 기기 간 이동, 포맷 버전 상호운용을 별도로 설계한다.
- 백업도 민감 데이터이므로 암호화/무결성 보호 및 복구 실험을 필수로 수행한다.
- 데이터 손상 시 복원 순서, 최종 성공 데이터, 실패 이유를 사용자에게 알려야 한다.
- 복구 설계를 위해 보안성을 떨어뜨리는 숨은 백도어 키를 만들지 않는다.

## 단위·통합 테스트

- 암호화/복호화 라운드트립, 빈 파일, 큰 파일, 잘못된 키, 조작된 파일, 잘린 파일.
- KDF·키 래핑 포맷 버전 업그레이드, 백업/복원, 전원 차단/쓰기 중단.
- 잠금 이후 기존 핸들/세션 접근 실패, 에러 로그에 비밀 데이터 없음.
- 동시 접근과 재시도 중 키 생명주기 일관성.

**금지:** 암호화 실패 시 평문으로 저장하기, 에러 해결을 위해 암호화 무력화하기, '암호화되었으니 무조건 안전하다'고 주장하기.
