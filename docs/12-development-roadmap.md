# 12. 개발 로드맵과 완료 정의

## 진행 순서

단계는 단순 날짜 계획이 아니라 **검증에 의존하는 순서**다. 핵심 게이트를 통과하지 못하면 정식 제품 단계로 올리지 않는다.

### Phase 0. 환경 조사 및 위험 검증

- 저장소, OS, Python/Rust/Qt/빌드 환경 조사
- `02-threat-model.md` 위협 모델 초안
- 5개 엔진 후보 문서/PoC 비교 (`03-engine-selection.md`)
- 프로필 데이터 경로·암호화·다운로드 파이프라인·네트워크 누출을 중심으로 실험
- ADR로 엔진 후보와 재평가 조건 기록

**완료:** 실험 로그와 검증/미검증 상태가 남고, 이후 구현 설계에 대한 근거가 있다.

### Phase 1. 일반 브라우저 개발자용 PoC

- 새 탭·주소창·탐색·기본 브라우저 창
- 테스트 서버와 로그인/스토리지 지속성 fixture
- 북마크·기록·다운로드 요청 UI 뼈대
- 실사용 데이터 금지 배너와 developer build 구분

**완료:** 기능이 재현 가능하고, 보안을 완료로 오인시키지 않는다.

### Phase 2. 독립 암호화 코어

- Rust 보안 라이브러리 PoC (적합성 검증 후)
- 인증 암호화·키 유도/관리·파일 스트리밍·변조 검출
- 키 포맷/버전·재시도/실패 테스트
- 백업/복구 설계의 기초 검증

**완료:** 잘못된 키/변조/강제 종료 등의 테스트 통과. 아직 프로필 통합 완료는 아님.

### Phase 3. 암호화 프로필 저장 계층

- 브라우저의 영구 프로필을 보호 경로에 통합
- 쿠키·사이트 데이터·기록·세션 정상 유지
- 종료/충돌/저장소 손상 시 복구
- 디스크/메모리/임시 경로 실험

**완료:** Gate A, B에 필요한 증거 확보. 실패하면 엔진/저장 아키텍처 재평가.

### Phase 4. 다운로드 금고

- 유형별 다운로드 데이터 보호 경로
- 파일 및 메타데이터 암호화
- 다운로드 목록·진행률·내부 열기(지원 가능 형식)·내보내기
- 부분 다운로드·취소·이름 충돌·가용 공간 부족 테스트

**완료:** Gate C 통과한 다운로드 유형만 사용자에게 지원 표시.

### Phase 5. 네트워크 가드

- 표준 보호의 HTTPS·추적 위험 감소 정책
- 프록시 연결/경로 실측 및 우회 차단
- DNS/WebRTC/IPv6/UDP/QUIC 검증
- Tor 지원은 별도 익명성 검증 전 출시하지 않음

**완료:** Gate D (해당 네트워크 모드별로 독립 통과).

### Phase 6. UX, 안정성, 접근성

- Chrome/Edge와 익숙한 흐름으로 정리
- Ctrl+T/L/H/J/D, 검색/다운로드/로그인/북마크 회귀
- 자동 잠금/복구·간결한 보안 경고·설정 단순화
- 반응성·리소스 사용량 측정 및 개선

**완료:** 설명 없이 주요 사용 시나리오 수행, 회귀 테스트 통과.

### Phase 6-1. 후속 엔진 전환을 위한 기반

- 엔진 초기화/뷰/기본 탐색 계약과 WebView2 어댑터 구축
- 기존 보안/다운로드/프로필 처리 경계를 보존하고 WebView2 전용 통합 지점 명시
- 자체 엔진은 별도 구현과 검증 후 다음 버전에서 평가. 첫 버전에는 선택 UI나 미검증 엔진 폴백 없음
- [전환 계획](17-engine-transition.md), [ADR-0009](decisions/ADR-0009-engine-boundary.md)

**완료:** 1차 경계 코드 및 회귀 검증. 자체 렌더러 완성을 뜻하지 않는다.

### Phase 7. 배포와 업데이트

- 설치·업데이트·롤백·제거 및 데이터 유지 테스트
- 서명/의존성/라이선스/보안 패치 정책
- `11-security-release-gates.md`에 따른 릴리스 판단

**완료:** 필수 게이트와 증거 링크가 존재한다.

## 첫 세션 목표

Phase 0 전체를 무조건 완료했다고 선언하지 말고, 가능한 실험을 실제 수행한다. 그 뒤 Phase 1의 **명시적으로 미검증 개발자용 브라우저 PoC**까지 구현한다. PoC 결과가 드러나기 전 대규모 본제품 기능 구현은 보류한다.

## 일감 관리

각 작업에 `목적 / 선행 조건 / 변경 파일 / 테스트 / 결과 / 위험 / 다음 작업`을 남긴다. 큰 단계는 테스트 가능한 작은 단위로 나누고, 수행하지 않은 테스트는 `NOT RUN`으로 표기한다.

### Phase 7 1차 구현 기록

[Windows 설치 및 업데이트](18-install-update.md): 내부 서명 패키지 생성 및 관리자 오프라인 유지보수 코드 추가. 실제 Windows 설치/업데이트/복구 검증은 NOT RUN이며 공개 배포 게이트는 미통과 상태를 유지한다.

첫 배포 목표는 Internal Alpha `1.0.0-alpha.1`이다. 합격 기준과 남은 작업은 [ADR-0010](decisions/ADR-0010-internal-alpha.md)을 따른다.
