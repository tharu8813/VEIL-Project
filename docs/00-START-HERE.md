# VEIL 개발 문서 시작점

> 문서 상태: 초기 기획 확정 / 핵심 기술은 검증 전  
> 대상: Windows 11 데스크톱 브라우저 / 초기 UI 한국어  
> 핵심 목표: **일반 브라우저만큼 익숙하게, 저장된 개인정보는 강력하게 보호**

## 반드시 구분할 상태

- **[확정]** 제품 방향이나 요구사항을 결정했다는 뜻이다. 구현 가능성이 입증되었다는 뜻은 아니다.
- **[가설]** 유력한 기술 대안이나 설계 제안으로, 실제 검증 전이다.
- **[검증 필요]** PoC, 소스/API 확인, 계측 또는 보안 테스트가 필요한 항목이다.
- **[차단]** 실패하면 실사용용 배포를 진행할 수 없는 보안 게이트다.

`기능이 돌아간다 = 보안 요구를 충족한다`로 판단하지 않는다.

## 문서 간 충돌 시 우선순위

1. `02-threat-model.md`와 `11-security-release-gates.md`의 안전 요구 및 출시 금지 조건
2. `01-product-requirements.md`의 필수 사용자 요구
3. PoC와 테스트가 입증한 사실 (`SECURITY_STATUS.md` 및 재현 가능한 증거)
4. 개별 설계 문서의 구현 제안

상충 시 조용히 임의 변경하지 말고 결정 기록(ADR)을 남긴다. 다른 문서에도 영향이 있으면 함께 수정한다.

## 초기에 확정된 제품 원칙

1. 일반 브라우저와 같은 검색·탭·로그인·사이트 이용 흐름을 유지한다.
2. 쿠키, 사이트 데이터, 북마크, 방문 기록, 세션은 기본적으로 **유지**한다.
3. 민감한 영구 로컬 데이터는 잠긴 상태에서 암호화로 보호한다.
4. 다운로드한 파일은 가능한 한 원본 평문을 일반 디스크에 쓰지 않고 금고에 보관한다.
5. 마스터 비밀번호·잠금 해제·외부 내보내기 등 꼭 필요한 경우에만 확인을 요구한다.
6. 네트워크 보호 모드는 방어 범위를 명확하게 구분하고, 보호 모드에서 우회 연결을 허용하지 않는다.
7. 구현되지 않거나 검증 실패한 보안 기능을 작동한다고 표시하지 않는다.
