# 08. 네트워크 보호 및 누출 방지

## 네트워크 위협의 종류

DNS 질의, 웹사이트가 보는 출발지 IP, TLS/SNI, WebRTC ICE 후보, IPv6, UDP/QUIC, 프록시 우회, 브라우저 지문, 트래픽 패턴을 구분한다. 로컬 데이터 암호화만으로 네트워크 익명성이 생기지 않는다.

## 모드 정의

| 모드 | 기본 동작 | 사용자에게 약속하지 않을 것 |
|---|---|---|
| 표준 보호 (v1) | 직접 인터넷 연결, HTTPS 우선, 추적 위험 최소화, DNS 보호 후보 | 실제 IP 은닉, 완전한 익명성 |
| 프록시/VPN 보호 (추가 검증) | 사용자가 설정한 경로로 연결, DNS/UDP/IPv6 우회 방지, 실패 시 연결 차단 | 프록시 제공자로부터의 완전한 익명성 |
| Tor 모드 (장기) | 별도 익명성 정책과 지문 방어·누출 시험 통과 시 제공 | Tor 프록시만으로 Tor Browser와 동등한 익명성 |

## 네트워크 정책 원칙

- 명시적으로 선택한 **보호 연결 모드**에서 경로가 끊어지면 직접 연결로 폴백하지 않는다.
- 표준 모드는 직접 연결 자체가 정상 경로이므로, 이 모드의 UX와 보호 모드의 Fail Closed 정책을 혼동하지 않는다.
- 프록시 설정 UI가 활성화됐다는 이유만으로 '보호 연결 작동'으로 표시하지 않는다.
- DNS 경로, WebRTC 우회, IPv4/IPv6, UDP/QUIC, WebSocket, 백그라운드 요청을 모두 검토한다.
- 브라우저 네트워크 계층과 OS 방화벽 사이에 정책이 새는 곳이 없는지 검증한다.

## 구현 후보

1. 엔진 내 프록시/네트워크 설정(공식 API로 가능한 범위 확인)
2. 연결 경로 실측 및 프록시/DNS 장애 대응
3. WebRTC 비프록시 UDP 제한 또는 지원 모드에서 차단
4. Windows Filtering Platform(WFP) 정책 강제 검토
5. 엔진 프로세스의 하위 실행 파일, 업데이트/진단 프로세스까지 범위 명시

WFP 기반 강제는 관리자 권한·서비스 설치·규칙 유지·제거 시 문제를 수반할 수 있으므로 사용자의 명시적 승인과 충분한 복구 절차를 설계한다.

## 테스트 행렬

| 시나리오 | 표준 모드 | 보호 연결 모드 |
|---|---|---|
| DNS 정상/장애 | 정해진 DNS 정책 검증 | 허용된 DNS 경로만 사용 |
| IPv4/IPv6 | 예상 인터페이스 검증 | 우회 연결 없어야 함 |
| WebRTC ICE | 정보 노출 범위 기록 | 실제 IP 직접 노출 여부 검사 |
| QUIC/UDP | 지원/정책 기록 | 미승인 UDP 직접 연결 차단 |
| WebSocket | 정상 호환성 | 허용 경로만 통과 |
| 프록시 프로세스 종료 | 해당 없음 | 모든 보호 대상 연결 중단 |
| Wi-Fi ↔ 유선 전환 | 정상 복구 | 정책 재적용 후만 재연결 |
| 절전·재개 | 정상 복구 | 정책 검증 전에 우회 연결 금지 |
| 네트워크 차단/재연결 | 오류 메시지 | 우회 없는 재개 |

## 1단계 구현 (2026-11-23)

[ADR-0006](decisions/ADR-0006-network-guard.md)에 따라 메뉴의 **네트워크 보호**에서 표준 보호와 프록시 보호(HTTP·SOCKS5)를 고른다. 변경은 다시 시작하면 적용되며 상태 표시줄이 표준 보호, `경로 확인됨`, `차단됨`을 구분한다.

- 표준 보호: 공용 주소의 `http://` 탐색은 `https://`로 연다. 실패하거나 HTTP로 되돌아가면 경고 페이지를 보여 주며, HTTP로 계속하는 선택은 VEIL 창의 빨간 막대(네이티브 컨트롤)에서만 할 수 있다. 페이지 안의 링크나 스크립트, 다른 사이트가 연 팝업에서는 다운그레이드할 수 없다. 엔진 추적 방지는 엄격이다.
- 프록시 보호: 엔진은 지정한 프록시만 쓰고(DIRECT 폴백 없음, 루프백 포함), WebRTC는 프록시를 거치지 않는 UDP를 쓰지 않으며 QUIC은 끈다. 다운로드 금고의 재요청도 같은 프록시만 쓴다. 설정이 잘못되면 시작을 거부한다.
- 로컬 자동 시험: `node tests/phase5/network-guard.mjs`. 프록시가 원 서버로 전달한 요청에 표시를 붙이고 표시 없는 요청(직접 연결)을 센다.
- 보안 DNS: 네트워크 보호 화면에서 DoH 제공자를 고르면 엔진이 그 서버로만 이름을 찾는다(실패 시 일반 DNS로 되돌아가지 않음). 로컬 시험 `node tests/phase5/dns-protection.mjs`(Git의 openssl 필요)는 로컬 DoH 응답기로 합성 이름 해석과 응답기 중단 시 실패를 확인한다. Windows DNS 캐시 확인은 대조 실행에서도 항목이 생기지 않아 판별력이 없으므로 참고로만 기록한다.
- 미검증(NOT RUN, 통합 VM): DNS 질의 경로(특히 SOCKS5 원격 이름 해석), 외부 IPv6, 실제 WebRTC ICE 후보, 절전·재개와 네트워크 전환, 엔진 밖 프로세스, WFP 수준 강제.

## UI와 진단

대시보드는 `선택됨`, `적용됨`, `경로 검증됨`, `차단됨/오류`를 구분한다. 외부 IP 또는 DNS 테스트 결과를 제공한다면 테스트 시각·범위·실패 이유를 함께 보여준다.

개인정보가 포함될 수 있는 상세 패킷/도메인 로그는 기본으로 수집하지 않는다. 진단 로그는 최소화·익명화·명시적 동의 정책을 따른다.

## 출시 게이트

프록시/Tor를 사용한 고강도 보호를 선언하기 전 네트워크 차단 및 누출 실측 테스트를 통과해야 한다. 불합격 시 기능은 실험실용으로만 유지한다.

### 단일 프록시 주소와 모드 검증 강화 (2026-11-25)

알 수 없는 네트워크 모드 값은 표준 직접 연결로 처리하지 않고 거부한다. 엔진 인수, 금고 HTTP 핸들러, DoH 설정 적용 모두 동일한 설정 검증을 거친다. 프록시 주소는 단일 ASCII DNS 호스트(국제화 이름은 Punycode), IPv4 또는 IPv6 리터럴만 허용하고 포트는 별도 1~65535 값으로 사용한다. 프록시 목록 구분자, 사용자 정보, URL 경로, 공백, 따옴표, IPv6 스코프 ID 등은 거부한다. 엔진과 금고는 정규화된 동일 호스트를 사용하며 엔진에는 기본 포트도 명시한다. Debug 설정 검증 및 CI 정적 계약을 추가했다. 실제 WebView2/HTTP 프록시 연결, DNS 누출, 외부 IPv6, Windows 네트워크 정책 및 패킷 검증은 NOT RUN이며 D2는 계속 미통과 상태다.

### 금고 HTTP 프록시 우회 결정 명시 (2026-11-25)

범용 WebProxy의 우회 판단 대신 고정 IWebProxy 구현을 사용한다. 모든 목적지에 같은 명시적 프록시 URI를 반환하고 IsBypassed는 항상 false다. 프록시 인증은 기존대로 미지원이며 직접 연결 폴백을 설정하지 않는다. UI 없는 .NET 10 회귀 시험을 CI에 추가했다. 합성 루프백 원 서버와 프록시를 별도 포트에서 열고 프록시 요청 줄 및 응답, 직접 원 서버 연결 없음, 프록시 종료 후 실패 및 직접 연결 없음 등을 검사한다. 이는 C# HTTP 핸들러의 로컬 동작 시험으로 WebView2, SOCKS5 실제 연결, DNS 및 외부 패킷, 실제 Windows VM 시험을 대신하지 않는다. D2 유지.

### 엔진 보안 DNS 설정의 검증 및 저장 (2026-11-25)

직접 입력 DoH는 길이 2048 이하의 단일 HTTPS 주소 또는 끝에 `{?dns}`가 붙은 GET 템플릿으로 제한한다. 사용자 정보·프래그먼트·공백/제어문자·역슬래시·다른 템플릿 구문은 거부한다. 기존 쿼리가 있는 GET 템플릿은 이번 범위에서 지원하지 않는다. Local State의 다른 JSON 값은 보존하고 고유한 CreateNew 스테이징 파일에 쓰고 디스크 flush 후 같은 디렉터리에서 교체한다. 저장된 JSON을 재검사하며 읽기·쓰기·교체·검증 오류 시 엔진 시작을 거부한다. 손상된 JSON은 시스템 DNS 선택에서도 자동 덮어쓰지 않는다. 별도 CI .NET 회귀에 주소 유효성, 설정 변경/해제, 기존 값 보존, Windows 공유 충돌, 스테이징 소유권 및 손상 JSON 거부를 추가했다.

**범위:** 이 DoH 설정은 WebView2 엔진에만 적용한다. 표준 모드 금고 HTTP 재요청은 별도 .NET 클라이언트와 시스템 DNS를 사용한다. 프록시 모드의 이름 해석은 프록시 종류와 설정에 의존한다. 이를 네트워크 설정 및 설정 요약에 표시하며 전체 애플리케이션의 DNS 누출 방지로 간주하지 않는다. 실제 엔진 적용/패킷/프록시+DoH 및 Windows VM 검증은 NOT RUN, D2 유지.
