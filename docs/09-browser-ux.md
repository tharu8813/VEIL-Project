# 09. 브라우저 UI/UX 및 사용성 규칙

## 최상위 원칙 [확정]

일반 사용자는 VEIL에서 Chrome/Edge의 기본 사용 경험을 거의 그대로 얻어야 한다. 보안 작업은 자동으로, 확인은 필수일 때만 수행한다.

## 일반 브라우저 기능 체크리스트

- 탭: 새 탭/닫기/이동/순서 변경/닫은 탭 복구/새 창/고정 탭/탭 검색
- 주소창: 주소 및 검색어 판단, 엔진 선택, 자동완성(개인정보 정책 필요)
- 탐색: 뒤로/앞으로/새로고침/중지/홈/전체화면/확대/페이지 내 검색
- 북마크: 추가/수정/삭제, 폴더 구조, 가져오기/내보내기 정책
- 기록: 검색·삭제·기간 선택
- 다운로드: Ctrl+J, 진행률, 완료/실패, 내부 열기/내보내기
- 사이트 권한: 카메라·마이크·위치·알림·파일 접근 등 최소 권한
- 로그인/사이트 데이터: 자동 보관, 사이트별 삭제, 추적 위험 낮추기
- 설정: 일반/개인정보/다운로드/보안·잠금/고급

## 사용자 확인 정책

| 상황 | 동작 |
|---|---|
| 탭 이동·검색·탐색·로그인 | 추가 보안 확인 없음 |
| 쿠키/기록/북마크 저장 | 자동 보호 |
| 금고에 파일 다운로드 | 별도 암호화 확인 없음 |
| 지원 형식 파일을 내부 뷰어로 열기 | 일반적으로 추가 확인 없음(콘텐츠 보안은 필수) |
| 잠금 해제·민감 비밀번호 전체 열람 | 사용자 인증 필요 |
| 파일 외부 내보내기 | 사용자 명시적 내보내기 동작 필요 |
| 연결 보호 해제·보안 설정 저하 | 위험을 간결하게 알려주고 명시적 확인 |
| 카메라/마이크 등 사이트 권한 | 표준 브라우저처럼 권한 요청 |

## 다운로드 UX

파일을 클릭하면 별도의 암호화 마법사 없이 다운로드된다. 목록은 일반 다운로드 관리자처럼 보이고, 내부 열기/내보내기/삭제 동작을 제공한다. 외부 열기에서 평문 파일 생성이 필요하면 이를 조용히 숨기지 말고 지원 정책에 맞는 명확한 UX로 처리한다.

## 메시지 설계

- 성공한 보안 동작에는 알림을 과도하게 띄우지 않는다.
- '보안 보호됨'은 실제 검증된 범위에서만 표시한다.
- 오류는 문제·영향·사용자가 할 수 있는 행동의 순서로 설명한다.
- 기술 용어는 고급 상세정보로 이동한다. 예: '파일을 안전하게 저장하지 못했습니다. 다운로드를 중단했습니다.'
- 보안 수준을 낮춰 호환성을 얻는 경우에는 명시적 사용자 동의와 되돌리기를 제공한다.

## 화면 규칙

- Windows의 글꼴 확대/DPI/다크 모드/키보드 접근성/탭 포커스 지원.
- UI 스레드에서 암호화·네트워크 검사·무거운 파일 작업을 실행하지 않는다.
- 설정은 기본적으로 간결하게, 전문 기능은 고급 영역에서 관리한다.
- 개인정보 보호는 사용자에게 부담을 넘기지 않으면서 상태를 오해 없이 보여준다.

## 디자인 완료 판정

보안 기능을 잘 모르는 사용자에게 간단한 사용성 테스트를 수행한다. 설명 없이 검색·로그인·북마크·다운로드·내보내기를 수행할 수 있어야 한다. 보안 경고가 의미 없이 반복되지 않는지 회귀 검사를 한다.

## Phase 6 북마크·방문 기록 관리 (구현, 검증 보류)

- Ctrl+B / Ctrl+Shift+O / Ctrl+H 및 메뉴는 네이티브 관리 창을 연다. 검색, 열기, 선택 삭제, 북마크 이름 편집, 기록 기간 필터 및 기간 전체 삭제를 지원한다.
- 저장은 기존 보호 프로필의 browser-state.json 경로와 원자적 발행 절차를 사용한다. 저장 실패 시 메모리 목록을 원복한다.
- 기간 삭제는 검색어와 독립적으로 확인한 항목만 삭제한다. VEIL 자체 방문 목록만 대상으로 하며 WebView2 탐색 기록·캐시·쿠키·사이트 저장소·백업 또는 디스크의 복구 가능 흔적을 삭제한다는 의미는 아니다.
- 기존 veil://bookmarks 및 veil://history 주소는 읽기 전용으로 유지한다. 변경 후 열린 목록 탭을 새로고침한다.
- **NOT RUN**: 사용자 요청에 따라 개발 중 일괄 검증으로 보류. 아래 검증을 마칠 때까지 완료/출시 가능으로 표기하지 않는다.

## Phase 6 사이트 권한 (FR-014, 구현·검증 보류)

- 메뉴 → 설정 → 개인정보 및 보안 → 사이트 권한에서 현재 HTTPS 출처 및 이전에 설정한 출처를 관리한다. 카메라·마이크·위치·알림의 기본값은 차단이며, 사용자가 요청 시 확인 또는 허용을 선택할 수 있다.
- 출처는 HTTPS 스킴·정규화된 호스트·포트의 조합이다. HTTP, 내부 페이지, 다른 출처의 프레임, 백그라운드 탭, 사용자 제스처 없는 요청, 미지원 권한은 거부한다. 동일 출처 프레임은 WebView2의 요청 출처 정보만으로 별도 구별하지 않는다.
- VEIL의 허용 목록은 기존 보호 프로필 browser-state.json에 저장한다. 엔진에는 요청 결과를 저장하지 않는다(SavesInProfile=false). 비정상 정책은 전체 기본 차단으로 복원하며 저장 실패 시 이전 설정을 유지한다.
- 확인 모드에서는 네이티브 대화상자의 명시적 승인만 허용하고 탐색 변경·탭 이동·종료 시 승인을 무효화한다. 여러 창에서 동시에 권한 대화상자를 띄우지 않는다.
- 권한 철회는 다음 요청에 적용된다. 진행 중인 미디어/위치 사용 또는 엔진 내부 캐시는 별도 검증 전까지 즉시 중단을 보장하지 않으므로 해당 탭을 닫도록 안내한다. 파일 접근, 클립보드, 화면 공유, 외부 URI 등은 새 허용 대상이 아니다.
- WebView2 API 근거: https://learn.microsoft.com/dotnet/api/microsoft.web.webview2.core.corewebview2permissionrequestedeventargs.savesinprofile
- **NOT RUN**: Windows 빌드, 실제 장치 및 인터넷 VM 검증은 일괄 검증 단계에서 실행한다.

## Phase 6 비밀번호 관리자 (FR-006 1차, 구현·검증 보류)

- 메뉴 → 비밀번호 관리자에서 독립 암호(최소 12자, 최초 확인 입력)로 별도 age 암호문 `passwords.age`을 연다. 사용자 이름·출처·비밀번호 전체를 암호화하며 browser-state.json, 다운로드 금고 키 및 WebView2 비밀번호 저장소와 분리한다.
- 기존 Rust age/scrypt(log_n=17) 및 인증된 원자적 발행 함수를 재사용한다. 기존 파일 인증 실패 시 교체하거나 평문으로 폴백하지 않는다. 암호 분실 시 복구되지 않는다. 별도 백업·키 회전 정책은 후속 작업이다.
- 암호와 JSON은 일회성 로컬 자식 프로세스의 stdin/stdout만 통과한다. 바이트·문자 배열은 가능한 범위에서 지운다. WPF/.NET 문자열, WebView2 스크립트 및 렌더러 메모리의 완전한 삭제·OS 덤프 방지는 보장하지 않는다.
- 계정은 직접 등록/갱신/삭제하며 목록은 비밀번호를 표시하지 않는다. 전체 값 열람은 별도 재인증을 요구한다. 클립보드 복사/내보내기·자동 폼 수집은 지원하지 않는다.
- 명시적으로 선택한 계정만 정확히 일치하는 활성 HTTPS 출처의 최상위 페이지에 채운다. 단일 가시 로그인 폼, 동일 출처 action, 비어 있는 비밀번호 필드만 지원하며 자동 제출하지 않는다. 사이트의 스크립트는 입력된 값을 읽을 수 있다. 탐색 경쟁·위협 경고·폼 스푸핑·렌더러 메모리 검증 전에는 실사용하지 않는다.
- WebView2 내장 비밀번호 자동 저장·일반 자동완성은 계속 비활성화한다. 기존 쿠키와 로그인 지속성은 변경하지 않는다.
- **NOT RUN**: Rust/C# 빌드, 자동 시험, 실제 브라우저 폼 및 보호 볼륨 추적은 일괄 검증 단계에서 진행한다.

## Phase 6 통합 설정 화면 (구현·검증 보류)

- 메뉴 → 설정 또는 Ctrl+, 로 네이티브 설정 창을 연다. 일반 / 개인정보 및 보안 / 네트워크 / 계정 및 비밀번호 / 다운로드 / 고급 및 정보 분류와 전체 항목 검색(한글·영문 키워드)을 제공한다.
- 설정 창은 기존 관리 기능의 진입점이며, 세부 창을 열기 전에 닫힌다. 네트워크·보안·사이트 권한은 통합 설정에서 접근한다. 북마크·기록·다운로드·금고·비밀번호 관리의 기존 메뉴 및 단축키는 빠른 접근을 위해 유지한다.
- 저장된 네트워크 설정과 현재 적용된 설정을 별도로 표시하며 변경 시 재시작이 필요하다. 네트워크 설정 저장에 실패하면 기존 값을 유지하고 실패를 표시한다. 정상 저장 후 모든 열린 창의 상태 표시를 갱신한다.
- SmartScreen은 엔진 설정 반영 상태와 사용자 선택을 구분한다. 위협 목록 부재·오류, 금고/비밀번호 저장소 상태 및 개발 프로필 여부를 표시하되 실제 보안 검증 통과로 해석하지 않는다.

## Phase 6 쿠키 및 사이트 데이터 관리 (FR-003, 구현·검증 보류)

- 설정 → 개인정보 및 보안 → 쿠키 및 사이트 데이터, 또는 Ctrl+Shift+Delete로 네이티브 관리 창을 연다. 기본 로그인/쿠키/사이트 저장소 유지 정책은 변경하지 않는다.
- WebView2 CookieManager의 전체 프로필 쿠키 조회 결과를 저장 도메인별 개수로 표시한다. 이름/값/토큰은 UI·파일·로그에 표시하거나 기록하지 않는다. 선택 삭제는 원래 저장 도메인(선행 점 포함)의 정확한 일치만 대상으로 하며 하위 도메인 일괄 삭제를 하지 않는다. 공유 도메인 쿠키의 삭제는 해당 쿠키를 사용하는 다른 사이트의 로그인에도 영향을 줄 수 있다.
- 사이트 저장소 출처 목록은 열린 탭/북마크/VEIL 기록에서 수집한 HTTP(S) 스킴·호스트·포트 조합이다. 모든 실제 저장소의 인벤토리가 아니다. 선택 출처의 사용량은 엔진의 Storage.getUsageAndQuota 보고값으로 확인할 수 있다.
- 출처별 삭제에는 네이티브 코드의 고정 Storage.clearDataForOrigin 호출과 명시된 storageTypes만 사용한다. LocalStorage/IndexedDB/CacheStorage/Service Worker/WebSQL/파일 시스템 대상이며 쿠키, 다른 출처, 전체 프로필 삭제로 폴백하지 않는다. 파티션 저장소·sessionStorage·디스크 캐시 및 실제 엔진 지원 범위는 별도 검증 대상이다.
- 전체 삭제는 사용자 선택/확인에 따라 Cookies, AllDomStorage, DiskCache만 조합한다. AllProfile/Settings/비밀번호/북마크/VEIL 기록/다운로드 금고를 대상으로 하지 않는다.
- 활성 다운로드가 있으면 시작을 보류한다. 열린 페이지/백그라운드 작업이 데이터를 다시 생성할 수 있으며, 삭제는 트랜잭션·포렌식 삭제·서버 로그아웃을 보장하지 않는다. 오류 시 부분 적용 가능성을 알리고 삭제 범위를 확대하지 않는다.
- API 근거: https://learn.microsoft.com/dotnet/api/microsoft.web.webview2.core.corewebview2browsingdatakinds 및 https://chromedevtools.github.io/devtools-protocol/tot/Storage/
- **NOT RUN**: 출처 정규화 및 도메인 일치 smoke를 추가했으며 빌드·실제 엔진/VM 검증은 일괄 검증으로 보류한다.

**찾아서 고친 결함**
- 비밀번호 관리자에서 마스터 암호가 틀리면 `InvalidDataException`이 처리되지 않아 브라우저 전체가 종료됐다. 후속 점검에서 같은 위험을 가진 `async void` 처리기를 모두 고쳤다(아래).
- 쿠키 도메인 삭제가 성공해도 엔진 반영 전에 다시 조회해 "일부 쿠키가 남아 있다"는 경고를 표시했다. 최대 2초 다시 확인한 뒤 보고한다.

**`async void` 처리기 점검 (2026-11-24)**: 전역 예외 처리기가 없어서, `async void` 처리기나 `async` 이벤트 람다에서 예외가 새면 브라우저 전체가 종료된다. 대상 25개(`async void` 22개, 람다 3개) 가운데 17개는 await 경로에 예외 처리가 없었다(새 탭, 닫은 탭 복구, 탭 닫기·다른 탭 닫기, 북마크·기록, 다운로드 목록, 페이지 내 검색 3개, 사이트 팝업, 네트워크·보안·검색·권한·설정·탭 검색). 6개(비밀번호, 사이트 데이터, 금고, 금고 창 작업, 강력 새로고침, 파비콘)는 처리기마다 다른 예외 목록을 써서 `InvalidDataException`, `TimeoutException`, `COMException`(엔진·렌더러 종료) 등이 빠졌다. 복구 가능한 실패 집합을 [RecoverableFailure.cs](../apps/desktop/RecoverableFailure.cs) 한 곳에 정의하고 모든 처리기가 이를 잡아 상태 표시줄에 알리도록 바꿨다. `NullReferenceException` 같은 프로그래밍 오류는 일부러 포함하지 않았다. CI의 정적 검사 [async-handlers.test.mjs](../tests/security/async-handlers.test.mjs)는 새 처리기가 이 규칙을 빠뜨리면 실패한다(수정 전 코드에서 8개 검출 확인). 엔진 강제 종료 중 각 처리기를 실제로 실패시키는 결함 주입 시험은 NOT RUN.

**관찰**: 같은 문서에서 알림을 허용한 뒤에는 사용자 동작이 없는 스크립트 요청도 `granted`를 받는다(엔진이 새 요청 이벤트를 만들지 않음). 새 문서와 철회 후에는 거부된다.

## Phase 6 다운로드 금고 UX (구현·검증 보류)

Ctrl+J의 네이티브 금고 진입점과 파일 검색·정렬·복구 필터·선택 인증 검사·명시적 내보내기를 추가한다. 내부 미리보기는 인증된 작은 UTF-8 TXT만 메모리에서 표시한다. PDF/이미지/외부 앱은 별도 보안 검증 전까지 지원하지 않는다. 상세 정책 및 일괄 검증 목록은 [07-download-vault.md](07-download-vault.md)를 따른다.
