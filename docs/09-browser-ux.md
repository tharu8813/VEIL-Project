# 09. 브라우저 UI/UX 및 사용성 규칙

## 최상위 원칙 [확정]

일반 사용자는 VEIL에서 Chrome/Edge의 기본 사용 경험을 거의 그대로 얻어야 한다. 보안 작업은 자동으로, 확인은 필수일 때만 수행한다.

## 일반 브라우저 기능 체크리스트

- 탭: 새 탭/닫기/이동/순서 변경/닫은 탭 복구/새 창/고정 탭(후속)
- 주소창: 주소 및 검색어 판단, 엔진 선택, 자동완성(개인정보 정책 필요)
- 탐색: 뒤로/앞으로/새로고침/중지/홈/전체화면/확대/페이지 내 검색
- 북마크: 추가/수정/삭제, 폴더 구조, 가져오기/내보내기 정책
- 기록: 검색·삭제·기간 선택
- 다운로드: Ctrl+J, 진행률, 완료/실패, 내부 열기/내보내기
- 사이트 권한: 카메라·마이크·위치·알림·파일 접근 등 최소 권한
- 로그인/사이트 데이터: 자동 보관, 사이트별 삭제, 추적 위험 낮추기
- 설정: 일반/개인정보/다운로드/보안·잠금/고급

## 필수 단축키

| 키 | 동작 |
|---|---|
| Ctrl+T | 새 탭 |
| Ctrl+W | 현재 탭 닫기 |
| Ctrl+Shift+T | 닫은 탭 복원 |
| Ctrl+L | 주소창 포커스 |
| Ctrl+D | 북마크 추가 |
| Ctrl+H | 방문 기록 |
| Ctrl+J | 다운로드 |
| Ctrl+F | 페이지 내 검색 |
| Ctrl+R / F5 | 새로고침 |
| Ctrl+Tab / Ctrl+Shift+Tab | 다음 / 이전 탭 |
| Ctrl++ / Ctrl+- / Ctrl+0 | 확대 / 축소 / 초기화 |

## 사용자 확인 정책

| 상황 | 동작 |
|---|---|
| 탭 이동·검색·탐색·로그인 | 추가 보안 확인 없음 |
| 쿠키/기록/북마크 저장 | 자동 보호 |
| 금고에 파일 다운로드 | 별도 암호화 확인 없음 |
| 지원 형식 파일을 내부 뷰어로 열기 | 일반적으로 추가 확인 없음(콘텐츠 보안은 필수) |
| 잠금 해제·민감 비밀번호 전체 열람 | 사용자 인증 필요 |
| 파일 외부 내보내기 | 사용자 명시적 내보내기 동작 필요 |
| 연결 보호 해제·보안 설정 저하 | 위험을 간결하게 알려주고 명시적 확인 |
| 카메라/마이크 등 사이트 권한 | 표준 브라우저처럼 권한 요청 |

## 다운로드 UX

파일을 클릭하면 별도의 암호화 마법사 없이 다운로드된다. 목록은 일반 다운로드 관리자처럼 보이고, 내부 열기/내보내기/삭제 동작을 제공한다. 외부 열기에서 평문 파일 생성이 필요하면 이를 조용히 숨기지 말고 지원 정책에 맞는 명확한 UX로 처리한다.

## 메시지 설계

- 성공한 보안 동작에는 알림을 과도하게 띄우지 않는다.
- '보안 보호됨'은 실제 검증된 범위에서만 표시한다.
- 오류는 문제·영향·사용자가 할 수 있는 행동의 순서로 설명한다.
- 기술 용어는 고급 상세정보로 이동한다. 예: '파일을 안전하게 저장하지 못했습니다. 다운로드를 중단했습니다.'
- 보안 수준을 낮춰 호환성을 얻는 경우에는 명시적 사용자 동의와 되돌리기를 제공한다.

## 화면 규칙

- Windows의 글꼴 확대/DPI/다크 모드/키보드 접근성/탭 포커스 지원.
- UI 스레드에서 암호화·네트워크 검사·무거운 파일 작업을 실행하지 않는다.
- 설정은 기본적으로 간결하게, 전문 기능은 고급 영역에서 관리한다.
- 개인정보 보호는 사용자에게 부담을 넘기지 않으면서 상태를 오해 없이 보여준다.

## 디자인 완료 판정

보안 기능을 잘 모르는 사용자에게 간단한 사용성 테스트를 수행한다. 설명 없이 검색·로그인·북마크·다운로드·내보내기를 수행할 수 있어야 한다. 보안 경고가 의미 없이 반복되지 않는지 회귀 검사를 한다.

## Phase 6 북마크·방문 기록 관리 (구현, 검증 보류)

- Ctrl+B / Ctrl+Shift+O / Ctrl+H 및 메뉴는 네이티브 관리 창을 연다. 검색, 열기, 선택 삭제, 북마크 이름 편집, 기록 기간 필터 및 기간 전체 삭제를 지원한다.
- 저장은 기존 보호 프로필의 browser-state.json 경로와 원자적 발행 절차를 사용한다. 저장 실패 시 메모리 목록을 원복한다.
- 기간 삭제는 검색어와 독립적으로 확인한 항목만 삭제한다. VEIL 자체 방문 목록만 대상으로 하며 WebView2 탐색 기록·캐시·쿠키·사이트 저장소·백업 또는 디스크의 복구 가능 흔적을 삭제한다는 의미는 아니다.
- 기존 veil://bookmarks 및 veil://history 주소는 읽기 전용으로 유지한다. 변경 후 열린 목록 탭을 새로고침한다.
- **NOT RUN**: 사용자 요청에 따라 개발 중 일괄 검증으로 보류. 아래 검증을 마칠 때까지 완료/출시 가능으로 표기하지 않는다.

### 일괄 검증에 추가할 항목

- [ ] Windows Debug/Release 빌드 및 기존 통합 시험
- [ ] 메뉴·단축키에서 관리 창 열기, 검색과 열기, Esc/닫기 및 다중 창 동작
- [ ] 북마크 추가·이름 변경·선택 삭제, 창 간 북마크 상태와 재시작 지속성
- [ ] 방문 기록 1시간/24시간/7일/30일/전체 필터, 경계 시간 및 기간 삭제 확인·취소
- [ ] 검색어 입력 중 기간 삭제 범위가 명시되며 다른 기간은 보존되는지 확인
- [ ] 저장 공간 부족 또는 쓰기 권한 오류 시 목록 원복 및 기존 상태 파일 보존
- [ ] 보호 프로필 재잠금·강제 종료와 관리 창 동시 동작, 보호 볼륨 외부 쓰기 추적
- [ ] 삭제가 쿠키·사이트 데이터·다른 프로필·다운로드 금고를 변경하지 않음
- [ ] 기존 읽기 전용 내부 주소 및 열린 탭 갱신, 키보드·DPI 접근성

## Phase 6 사이트 권한 (FR-014, 구현·검증 보류)

- 메뉴 → 사이트 권한에서 현재 HTTPS 출처 및 이전에 설정한 출처를 관리한다. 카메라·마이크·위치·알림의 기본값은 차단이며, 사용자가 요청 시 확인 또는 허용을 선택할 수 있다.
- 출처는 HTTPS 스킴·정규화된 호스트·포트의 조합이다. HTTP, 내부 페이지, 다른 출처의 프레임, 백그라운드 탭, 사용자 제스처 없는 요청, 미지원 권한은 거부한다. 동일 출처 프레임은 WebView2의 요청 출처 정보만으로 별도 구별하지 않는다.
- VEIL의 허용 목록은 기존 보호 프로필 browser-state.json에 저장한다. 엔진에는 요청 결과를 저장하지 않는다(SavesInProfile=false). 비정상 정책은 전체 기본 차단으로 복원하며 저장 실패 시 이전 설정을 유지한다.
- 확인 모드에서는 네이티브 대화상자의 명시적 승인만 허용하고 탐색 변경·탭 이동·종료 시 승인을 무효화한다. 여러 창에서 동시에 권한 대화상자를 띄우지 않는다.
- 권한 철회는 다음 요청에 적용된다. 진행 중인 미디어/위치 사용 또는 엔진 내부 캐시는 별도 검증 전까지 즉시 중단을 보장하지 않으므로 해당 탭을 닫도록 안내한다. 파일 접근, 클립보드, 화면 공유, 외부 URI 등은 새 허용 대상이 아니다.
- WebView2 API 근거: https://learn.microsoft.com/dotnet/api/microsoft.web.webview2.core.corewebview2permissionrequestedeventargs.savesinprofile
- **NOT RUN**: Windows 빌드, 실제 장치 및 인터넷 VM 검증은 일괄 검증 단계에서 실행한다.

### 일괄 검증 추가 항목

- [ ] 기존 프로필/새 프로필 기본 거부, 손상된 설정·중복·미지원 권한 fail-closed
- [ ] HTTPS 출처별 호스트/포트 격리, HTTP·내부 페이지·교차 출처 iframe·백그라운드·제스처 없는 요청 거부
- [ ] 카메라·마이크·위치·알림의 실제 허용/거부/확인 동작 및 Windows 권한 제한
- [ ] 확인 취소·창 닫기·동시 요청·탐색 중 응답·탭 이동·잠금/강제 종료 시 허용 누출 없음
- [ ] 다중 창·재시작 후 VEIL 설정 복원 및 철회 후 새 요청 거부, 기존 엔진 권한 상태/캐시 우회 여부 확인
- [ ] 디스크 부족·쓰기 실패 시 설정 유지, 보호 볼륨 밖 기록 및 실제 장치 접근 중단 범위 확인
- [ ] 기존 탐색·다운로드 금고·외부 URI 차단·키보드 접근성 회귀
