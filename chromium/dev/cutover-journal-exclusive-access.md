# Synthetic journal operation exclusion

PR #170 exact head c38a337e4a1fdd01f52e48d1d848a9c8920e6644 [Windows CI](https://github.com/tharu8813/VEIL-Project/actions/runs/45694708849) PASS native fixture write/flush/no-replace rename/readback and pending/gap/malformed/hardlink refusal, injected ACL positive only; merged 55661a5e1c22e326c35affc8768bb473bb2fcadc.

Both fixture journal read and append now require an existing zero-byte maintenance.lock in the exact synthetic directory, opened GENERIC_READ with sharing zero, retained for the entire individual operation (including history validation, write, rename and final recheck). No lock creation, deletion or truncation by library; absent, hardlink, nonempty, unsafe path/ACL/ADS or unavailable lock refuses. Sharing violation reports busy immediately. Existing native strict object policy remains required. Tests hold the lock in PowerShell while separate native process attempts read and append; require busy, preserved output and no pending file. After release run normal regression, missing/nonempty/hardlinked lock refusal. Test setup deliberately recreates only its own temporary lock. Exact-head CI NOT RUN at commit.

Cooperative per-operation exclusion, NOT a transaction-wide maintenance lease across multiple calls, global service/update exclusion, authenticated storage, anti-rollback, crash/power-loss proof or protection against non-cooperating processes with write privileges. Handle closes on return; process death releases the share restriction but does not certify safe recovery. No real product registration, broker, service or profile changes. Existing WebView2/Rust/broker/installer unchanged. Actual upstream Windows build still required.
