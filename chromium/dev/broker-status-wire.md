# Native broker Status wire experiment (development only)

PR #142 exact head b2cb65445ea2a19ce81fc4ff8f56e8c82da3958a [Windows CI](https://github.com/tharu8813/VEIL-Project/actions/runs/45664325691) PASS, retained-handle GUID matches independent mount API for synthetic directory; merged 4e2222acbc8e968245281ca8ddaf747b8c58aee1. No BitLocker proof.

Existing Protocol.cs blob 577631a825c47cf03cf11c25219397a5f5d430d4 and BrokerClient.cs blob a9418e46a353ddff886f052d2da8df9b93d6260a define newline-delimited JSON, 4096-byte payload cap, registered volumeId, Status/Attach/Unlock/Lock/Detach, success status fields, and error responses. This standalone experiment encodes ONLY Status for conservative ASCII volume identifiers (a subset, not a change to existing registration), decodes a complete bounded frame with exact schema, field type checks, duplicate/unknown/missing rejection, ASCII escapes, canonical GUID and detached consistency. It preserves output on malformed/refused replies; successful parsing returns snapshot only, not trusted evidence. No passwords, path arguments, mutation commands or pipe connection. A narrow parser is used for this independent experiment, not a general-purpose JSON implementation; actual Chromium integration should review use of upstream base JSON facilities and verify real serializer interoperability. Linux C++17 synthetic wire fixtures, malformed/truncated/multi-frame cases and length limits NOT RUN at commit. Actual native pipe transport, server identity, timeout/cancellation, service/user ACLs, fresh unlock/session binding and runtime NOT RUN. Existing broker/WebView2/Rust and security gates unchanged.
